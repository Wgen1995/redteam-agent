# P0 · 授权门（方法论指令）

入口：交战区目录可用，且无既有 goal 或处于 resume 态（state-rebuild PASS）。一切主动操作的前提——人在回路，不允许 AI 猜测补全任何一问。

## duty（命令序列）
序列：八问问卷+业务问卷 → add-goal → scope/creds 落账（含 oob/account-grant/amendment 语义）→ 授权书扫描件入 evidence（双哈希）→ SKILL 版本+tools.lock 哈希+触发器目录版本（append-timeline 落 triggers-catalog <TRIGGERS.md 版本>，PROTOCOL §6①）→ tanyin-egress compile → tanyin-canary deploy。

八问表落账对照（设计 §8.1）：

| # | 问题 | 落账 |
|---|---|---|
| ① | 目标（域名/IP/网段/源码包） | add-goal（goals.target）+ add-scope --kind=include |
| ② | 范围（允许的攻击类型/深度） | add-scope include（permitted_actions） |
| ③ | 排除项（生产库/第三方组件/时段） | add-scope --kind=exclude |
| ④ | RoE（发现高危怎么办/凭据处理/备份状态确认） | add-goal（objective 附注）+ approve |
| ⑤ | 报告/沟通语言 | add-goal（goals.language） |
| ⑥ | 测试时间窗（跨天再确认） | add-goal（valid_from/until + window） |
| ⑦ | 紧急联系人 | add-goal（emergency_contact） |
| ⑧ | 测试账号与数据分级（账号/角色；数据允许流向哪个 LLM API） | add-cred --kind=static-cred + add-scope --kind=account-grant |
| + | 业务问卷（系统类型/核心业务流） | add-goal（business_context——P2 矩阵生成与 biz 标记输入） |

落账语义：oob=界外观察白名单（只读观察放行）；account-grant=账号授权面；amendment 不经本门改写——客户扩授权走 P3 scope-amended 事件（amend-scope，须 approvals）。凭据真值只入 vault，账本只见 secret_ref 占位符。

## entry 检查单
- 交战区目录可用（13 表齐备）
- 无既有 goal，或处于 resume 态：verify-chain PASS 且 state-rebuild PASS（撕裂态先走恢复协议）

## exit 断言
- tanyin-phases gate --goal-dir <D> --phase P0 --timestamp <T>，断言三条：
  1. validate --tables goals,scope,creds（三表结构合法）
  2. scope-coverage（include+exclude+oob 齐备）
  3. verify-chain（链一致）
  on_fail=halt：人工处置后原地重评，不得跳门进 P1。

## 回边
- 本门无事件回边（back_edges 不涉及 P0）；断言失败=halt 原地重评。
- 授权修订不回本门改写：客户扩授权走 P3 scope-amended（amend-scope+approvals 链）。
