## 场景

把侦察得到的版本/横幅证据变成按优先级排序的 CVE 待验证清单。读只查询工具(关键词检索+CVE 详情);评分排序(CVSS 基础分→可利用性→实际暴露面);版本适用域核对(cpe 范围匹配);候选过多时按高危与 RCE 类优先。

## 步骤

1. 提取产品+版本:服务横幅/响应头/JS 包/登录页脚/包清单,精确版本串优于裸名【纪律:无】
2. CVE 库查询:产品+版本关键词检索,高危命中拉详情记录【纪律:L3】
3. 评分排序:CVSS 基础分→利用可得性→实际可达性【纪律:无】
4. 版本适用域核对:目标版本对 CVE 受影响范围逐条匹配(横幅不等于漏洞;发行商可能原地补丁)【纪律:无】
5. 落档:带 CVE-ID/CVSS/映射证据登记;未确认标 needs-manual-review【纪律:无】

## 工具引用

- CVE 检索工具(NVD 数据源同型): 关键词与详情查询(只读,不对目标出网)
- 指纹识别工具: 精确版本提取

## 纪律标注

- L3: 步骤 2 CVE 数据源查询为对第三方库的出网读,走 egress 白名单
- 外发: 无(查询不携带目标数据,仅产品名+版本)
- 回滚: 无

## 证据标准

- 产品/版本证据→CVE 候选的映射记录
- 每候选的适用性判定(适用/不适用/已补丁/待人工)
- 第三方 PoC 仓库线索仅作线索登记,不盲跑

## 边界

- 不执行任何利用;不发送攻击性验证载荷
- 第三方 PoC 视为未验证代码,不直接对目标运行
- 法律敏感:本卡只写方法论与判定标准;示例仅限本方靶场内验证,不提供现成可执行武器(载荷/命令/利用代码)。
