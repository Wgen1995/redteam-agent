## 场景

首次接触裸目标的侦察入口:DNS 解析+存活探测→端口扫描+服务指纹→子域枚举→Web 目录/敏感文件→WAF/CDN 识别→技术栈指纹。为 CVE 匹配与攻击路径分配提供事实输入。

## 步骤

1. DNS 解析+存活探测【纪律:无】
2. 端口扫描+服务指纹【纪律:无】
3. 子域枚举【纪律:无】
4. Web 目录与敏感文件探测【纪律:无】
5. WAF/CDN 识别【纪律:无】
6. 技术栈指纹(CMS/框架/中间件版本)并产出画像工件【纪律:无】

## 工具引用

- DNS 解析库: 解析与记录
- nmap 同型: 扫描
- 指纹识别工具: 技术栈

## 纪律标注

- L3: 无(探测在授权目标内;被限速则降速或暂停,不绕过)
- 外发: 无
- 回滚: 无

## 证据标准

- recon_profile+port_scan_result+service_fingerprint(三必产)
- min_attempts=4;饱和即推进下一阶段

## 边界

- 不执行主动漏洞利用;不发破坏性请求
- 不暴力破解不密码喷洒;不绕过速率限制
- 不自动扩展到未出现的关联域名/地址
- 法律敏感:本卡只写方法论与判定标准;示例仅限本方靶场内验证,不提供现成可执行武器(载荷/命令/利用代码)。
