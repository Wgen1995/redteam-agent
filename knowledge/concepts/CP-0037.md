## 场景

逻辑缺陷:竞态条件(双重提交/并发消耗);流程跳过(支付步骤绕过);价格篡改(客户端金额修改);权限逻辑(角色检查不完整);IDOR(对象引用越权)。

## 步骤

1. 业务流程建模:状态机/关键校验点/角色与对象关系【纪律:无】
2. 越权面:水平与垂直对象引用对照(双账户)【纪律:无】
3. 流程面:可跳步与状态回退路径分析【纪律:无】
4. 竞态面:并发窗口验证(测试数据;最小并发)【纪律:无】
5. 数值面:边界与精度篡改验证(测试订单)【纪律:无】
6. 业务影响评估与报告【纪律:无】

## 工具引用

- 竞态测试工具: 并发窗口验证
- API 测试代理: 请求篡改与对照
- 双测试账户: 越权对照

## 纪律标注

- L3: 无
- 外发: 无
- 回滚: 无(全部用测试数据;订单类验证后走取消/退款复原)

## 证据标准

- 完整操作步骤序列
- 逻辑缺陷利用成功证明(余额/权限/流程)
- 业务影响评估

## 边界

- 不得造成真实经济损失
- 验证用测试数据;完成后复原
- 法律敏感:本卡只写方法论与判定标准;示例仅限本方靶场内验证,不提供现成可执行武器(载荷/命令/利用代码)。
