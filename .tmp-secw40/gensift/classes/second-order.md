# second-order ｜ 二阶注入（CWE-89 变体：污点经存储复活）

> band: 0 ｜ 模式表: `patterns/second-order-{java,ts,python}.pattern` ｜ fixture: `fixtures/enum/second-order/`
> 来源/校准: v1.3.2 定稿基线 ｜ 最近校准: S1 起步集（2026-08） ｜ 演化纪律: append-only+人工批准（CALIBRATION 通道，B-115/B-116）
> 定级阶梯: 写侧入口可控 + 回读侧再拼接进危险 sink + 净化只覆盖写侧 → High（同 CWE-89）；回读侧为后台任务/异步消费（无请求语境观测）→ 盲二阶，High 需 OOB/时间差证据；回读值仅作展示/等值绑定 → 降 Medium 或关闭（前提引文）
> 与 sqli 的分工: **sqli 管"同请求直达"（入口→sink 单请求链）；second-order 管"跨请求复活"（写入请求 ≠ 触发请求，判定围绕 persisted_read 配对）**。同一 sink 位置两种链都成立时按本类报、sqli 卡不因此剪。发现侧重叠的 cand_id 配对规则见定稿 §3：source_seq 为 persisted 型时允许配对到写侧入口的 fw 卡，配对走 Reporter 拼链的"假设点必复核"机制。

## ① 定义与危害
用户可控 payload 经入口**写入存储**（DB 字段/缓存键值/上传文件名/session 属性/日志字段/搜索索引），在**另一个请求或另一条执行链**中被回读并拼进危险构造——写入时点的校验/转义挡不住回读时点的解释，攻击者改变的不是本次查询而是"下一次查询"。危害面同 sqli（拖库/堆叠/盲注）外加跨用户复活（A 写入、B 触发）与延迟触发（后台任务/报表导出）。

## ② Source
写侧 = 常规入口全集（HTTP 参数/消息体/上传文件名/头部，同 sqli ②）。回读侧 = **persisted_read**：DAO/Repository/ORM 查询返回点、缓存 get、结果集取列、文件/配置回读——回读点作为 source 的枚举归 langpack（entry_type=persisted_read，模式唯一居所规则见 pattern-ownership）；本类模式表只锚"回读值再拼接"形态（§③）。**成本闸门（定稿 §3）**：persisted_read 型 source 标 band=weak 入清单但**不预发 fw 卡**；仅当某 sink 的 bw 卡追踪不到常规 source 时，才对可能供给它的回读点按需发追踪卡（origin_ref=该 bw 卡）。回读值默认 unknown 可控性，禁止在 VERIFY 中当"不可控"反证。

## ③ Sink 模式表指针
`patterns/second-order-java.pattern` / `second-order-ts.pattern` / `second-order-python.pattern`（机器直读，逐行一条，不并串）。锚点 = 回读调用 + 同表达式再拼接（findByX/getByX/queryForObject/缓存 get/结果集取列后接 `+`/模板插值/f-string）。**弱锚是设计属性**：命中 ≠ 二阶成立（拼接目标可能是日志/展示），配对判定全靠 C1–C6；pattern 只负责把"回读值被再拼接"的位置捞进分母。

## ④ Propagator
回读值到 sink 的透传：getter 链（u.getNickname()/user.remark）、解构（const {nick} = user）、JSON 字段二次取值（cfg["nick"]/payload.data.v）、缓存反序列化产物、ORM 关联对象（user.profile.remark）。跨方法/跨请求保守传播——**跨请求是本类传播的常态而非例外**。

## ⑤ Sanitizer（决策表三值）
回读侧 sink 位置参数化绑定 `?`/`$1`/白名单列名映射 → **强**（同 sqli 决策表，按 sink 语境查值）；写侧入库 escape/黑名单/长度截断 → **弱**（净化语境是写侧存储，回读侧 sink 语境不同——"净化与载荷形态不匹配"的典型形态）；写侧参数化 INSERT → 对二阶**无效**（绑定救的是写入语法位，不改变存储的值——不得据此剪卡）；存储层约束（NOT NULL/枚举列/外键） → **上下文条件（只产 hint，禁 kills）**；`if(strict)` 才启用 → 同上下文条件并显式挂 `requires_config`。**多段净化看全部，写侧任何净化不能替代回读侧 sink 位置的净化。**

## ⑥ 判定流程（编号条目）
C1 回读侧是否存在存储回读点（DAO/ORM 查询返回、缓存 get、结果集取列、文件/配置回读）？｜期望引用:回读调用行（findByName/getByX/queryForObject/cache.get/getString）｜推翻反例:值来自本请求入口直达无存储中介（归 sqli 同请求链）｜反向:回读藏在工具类封装（getLabel(cacheKey)）内层
C2 写入侧是否存在外部可控入口把同名字段写进该存储？｜期望引用:写侧入口签名与写入行（save/insert/update/put/setAttribute/上传文件名落库）｜推翻反例:字段仅服务端自产（审计时间戳/自增列/后台枚举映射）｜反向:写入经低敏入口（资料页昵称/备注/文件名）——鉴权弱不排除可控
C3 写入键与回读键是否同一存储命名空间（表/实体/缓存键前缀/索引名）？｜期望引用:两侧实体名、表名或键名拼法｜推翻反例:同名异库或带租户前缀隔离且前缀服务端拼接｜反向:经 ORM 关联对象间接同源（user.profile.remark）
C4 回读值是否在下游被"再拼接"（字符串拼接/模板插值/f-string/进解释器）？｜期望引用:回读值变量到 sink 的构造行±3行｜推翻反例:回读值仅作等值绑定参数或展示输出｜反向:回读值先落第二层缓存/日志/索引再被第三请求读出（多跳复活）
C5 净化是否覆盖回读侧 sink 语境（决策表按 sink 语境查值）？｜期望引用:写侧净化行 + 回读侧 sink 语境引文两处｜推翻反例:回读侧 sink 位置存在强净化（绑定/白名单）且形态匹配｜反向:写侧 escape 后回读侧仍拼 SQL/命令/路径（语境错配——写侧净化不剪卡）
C6 回读侧触发链是否可达且可观测（路由/后台任务/管理端/异步消费）？｜期望引用:回读侧入口注解或调度声明 + 响应/输出构造行｜推翻反例:回读侧代码不可达（feature 关闭且有边界证据）｜反向:后台任务或导出回读（无 HTTP 回显——盲二阶，需 OOB/时间差证据）

## ⑦ 常见误报（FP 卡，只增+deprecate 留痕）
FP-1 回读+拼接但目标是日志/展示字符串（非解释器 sink）——弱锚命中是设计属性，C4 反证引文。
FP-2 回读值来自服务端枚举映射（状态码→文案表）——C2 推翻形态（写入侧无外部入口）。
FP-3 同请求直达链（入口→sink 无存储中介）——归 sqli（分工见页首），C1 反例形态。
FP-4 ORM 关联对象取值但该字段从不接受用户写入（仅后台维护）——C2 推翻形态。
FP-5 写侧参数化 INSERT 被当作"已净化"——绑定救写入语法位不改变存储值（C5 反向），不是二阶反证。

## ⑧ 常见漏报与绕过（bypass 提示单——去尝试，不是去阅读）
B1 多跳复活：写入→中间缓存/搜索索引/日志→第三请求读出再拼（C4 反向）。
B2 编码形态入库（base64/URL/hex/Unicode 转义）——回读侧解码后拼接，编码不是净化。
B3 触发链藏在后台任务/报表导出/CSV 生成（无请求语境，观测靠 OOB/时间差）。
B4 同名字段经 ORM 关联对象间接复活（user.profile.remark——C3 反向）。
B5 写侧长度限制截断 payload——截断不是净化，短 payload 仍可注。
B6 缓存键含用户输入导致读到他人写入值（缓存投毒变体——跨用户复活）。

## ⑨ 利用前提与定级阶梯
见页首；High 验收：写入→存储→回读→sink 四段链每段有引文，专业审查者无需长篇推测即接受"写入点可控且回读点会拼"。
降级反例（B-109——出现下列形态时不应保持 high/critical，降级须引文）: 回读值仅内部消费、无 sink 汇聚点 OBS（落库后只作展示）→ 降 medium 以下

## ⑩ 根因修复
回读侧一律按 sink 语境参数化/白名单——**不信任存储值（"DB 里的数据也是输入"）**；写侧净化不能替代读侧绑定；用户可写字段入库前做语境无关 reject（而非 escape）；DAO 层禁止拼接入口（同 sqli ⑩，作用于回读侧）。

## ⑪ 跨边界提示
写入方与读出方常为不同服务（各自 DAO/ORM 指向同库——读侧语境决定危害面，写侧无害不代表链路无害）；消息队列、搜索索引、CDN 缓存是常见二阶载体；CI/CD 配置入库后被部署脚本回读拼接（二阶命令注入变体）；A 写入 B 触发的跨用户复活使"写入侧有鉴权"不能剪读侧卡。
