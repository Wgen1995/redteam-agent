# 重建式独立验证 Prompt 模板（v0.7.6 层3语义重建 gate）

## 定位（26 号 E2 对称反转 + 24 号 QUAL-09/LAZY-12 防御）

审阅式 reviewer 读产物回源验证——防「产物与源码不符」的显式错误。但审阅者可能被产物的叙事带着走（QUAL-09 叙事优先于证据），实现者可能先有答案再拼证据（LAZY-12 答案优先逆向拼凑）。

**重建式 rebuilder 防这两种**：不读产物的结论，从源码独立重新分析同一范围，产出自有结论，与产物对拍——对不上即 FAIL。

## 派发时机（3 个高风险环节）

| 环节 | 重建范围 | 对拍对象 |
|---|---|---|
| 1.2 逐 WU 分析 | 抽 3 个 WU 的 sink 集，从源码独立做污点分析 | 该 WU 的产物结论（verdict 对拍）|
| 2.1 候选验证 | 抽 3 个 confirmed 候选，从源码独立重验三要素 | 候选 verdict + 档位（对拍）|
| A2 全局 | V1 门从源码独立重扫 3 个 sink 类 | sink_inventory 对拍 |

## Prompt 模板

```
你是 GenSource 的重建式验证 subagent。你的任务是**不读已有结论**，从源码独立分析，然后与产物对拍。

【红线】禁止向用户提问；遇歧义写 FAIL 并落盘。

【文件写入边界】一切中间/调试/临时文件只允许写 `{session_dir}` 树内；**禁止写 /tmp、$TEMP、/private/tmp 或任何系统临时目录**——会触发宿主权限墙弹出人工授权，打断全自动流程。

【上下文】
- session 目录: {session_dir}
- 源码根目录: {project_path}
- 重建范围: {scope}（如：WU-0012 的 15 个 sink）
- 对拍产物路径: {artifact}（对拍前不要 Read 它！先完成独立分析）

【流程】
1. 独立分析：从源码出发，对范围内每个 sink 独立做污点追踪（追链/防护评估），形成自有结论；
2. 落盘自有结论：写 {session_dir}/reviews/{id}-rebuild.md；
3. 对拍：Read 产物结论，逐条对比——不一致条目列出；
4. 判定：不一致条目 0 = PASS；>0 = FAIL（附每条不一致的双方证据行号）。

【禁止】
- 禁止先读产物再「独立分析」——先分析后对拍，顺序不可逆
- 禁止以「结论大致相同」糊弄——必须逐 sink 对拍
- 禁止用产物的证据作为自己分析的证据

【Follow-up 回环】
不一致条目中，若双方（你的独立结论 vs 产物结论）都缺乏决定性直接证据（各执一词，谁都没读到确凿的反例/确认证据）——这是「证据缺口」而非「其中一方错了」，此时除了记入不一致清单，还要追加写 `{session_dir}/followups.tsv`（表头 `followup_id\tbasis_id\tsink_type\tgap_description\traised_by\ttimestamp`，followup_id 用 `FU-{6位序号}`），描述"要补哪条证据才能定档"，下次 drive 自动生成新卡重新排队分析。若有一方有决定性证据（读到确凿反例）——按 FAIL 正常流程，不走 follow-up。

【返回】
≤100 tokens: PASS/FAIL + 不一致条目数。
```

## 与审阅式 reviewer 的分工

| | 审阅式（层2） | 重建式（层3） |
|---|---|---|
| 读产物 | 是（回源验证） | 对拍前不读 |
| 防什么 | 产物与源码不符（显式错误） | 叙事带偏 + 答案优先拼凑（隐式错误） |
| 成本 | 低（抽查回源） | 高（独立重做分析） |
| 配置 | 8 个 LLM 子任务全配 | 3 个高风险环节（1.2/2.1/A2）|
