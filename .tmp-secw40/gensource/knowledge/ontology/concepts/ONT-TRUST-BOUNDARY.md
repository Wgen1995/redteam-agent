# ONT-TRUST-BOUNDARY：信任边界

## 定义

信任边界是划分不同信任级别主体或数据的分界线——数据或执行流跨越信任边界时，信任假设发生改变，需要进行验证或授权决策。

## 包含边界

- 网络边界：公网与内网之间、DMZ与内网之间
- 进程边界：不同进程之间的IPC/RPC调用
- 租户边界：多租户系统中不同租户之间的隔离边界
- 权限边界：普通用户与管理员权限之间
- 数据信任级别边界：用户输入（不可信）与内部数据（可信）之间
- 信任域边界：微服务架构中不同服务之间的信任域

## 排除边界

- 攻击面（ONT-SURFACE）不是信任边界——攻击面是暴露的接口集合，信任边界是划分信任级别的分界线
- 守卫（ONT-GUARD）不是信任边界——守卫是边界上的授权检查机制，边界是守卫所在的位置
- 资产（ONT-ASSET）不是信任边界——资产是被保护的对象，信任边界是保护范围的划分

## 关系

| 关系类型 | 目标概念 | 说明 |
|---|---|---|
| `crosses` | ONT-SURFACE | 攻击面可能跨越信任边界 |
| `guarded_by` | ONT-GUARD | 信任边界由守卫保护 |
| `contains` | ONT-ASSET | 信任边界包含特定信任级别的资产 |

## 正例

```
[公网/不可信] ──信任边界──> [内网/可信]
                ↑
          Guard在此检查
```

```python
# 多租户系统中的租户边界
def get_tenant_data(request):
    tenant_id = request.user.tenant_id  # 租户边界
    # 跨租户访问需要在边界处检查
    return Data.objects.filter(tenant_id=tenant_id)
```

## 反例

```python
# 这只是普通的函数调用，不涉及信任级别变化
def add(a, b):
    return a + b  # 没有信任边界跨越
```

## 代码信号

- 网络层：防火墙规则、安全组配置、入站路由定义
- 应用层：认证中间件、租户隔离逻辑、权限检查装饰器
- 架构层：微服务间调用边界、API网关配置
- 部署层：Docker网络隔离、Kubernetes NetworkPolicy
