# Org Graph（逻辑角色索引视图）

## 定位

本文件帮助理解“谁执行、谁复核、谁批准”，不创建固定多Agent编制，也不定义新的权限。字段权限以`../contracts/field-ownership-table.md`为准，人工边界以`human-in-the-loop.md`为准，subagent能力与降级以`deployment-environment.md`为准。

```text
用户 / 人工授权方
        ↓
宿主 / 顶层调度角色
        ├─ 范围与语境角色
        ├─ 候选发现协调角色
        │    ├─ 模式发现角色（可选subagent）
        │    ├─ 业务逻辑角色（可选subagent）
        │    └─ 横向差异角色（可选subagent）
        ├─ 验证分析角色
        │    └─ 独立挑战者（优先独立subagent）
        ├─ PoC角色
        ├─ 修复生成角色
        │    └─ 独立修复复核角色
        ├─ 报告投影角色
        └─ 知识演进提案角色
                 ↓
             人工批准写入
```

| 逻辑角色 | 核心职责 | 独立性要求 | 降级边界 |
|---|---|---|---|
| 用户/人工授权方 | 确认范围、权限、不可逆决定和知识晋升 | 人工身份，不可由Agent模拟 | 缺决定时`blocked` |
| 顶层调度角色 | run-state、路由、WU派发、串行汇聚、Gate-1 | 不承担漏洞终态判断 | subagent不可用时可接管普通执行，不得冒充独立复核 |
| 三类发现角色 | 各自执行模式/业务/横向差异发现 | 可并行，结论汇聚前互不覆盖 | 无subagent时顺序执行 |
| 验证分析角色 | 写验证与定级字段 | 与候选发现字段隔离 | 不得改candidate身份 |
| 独立挑战者 | Gate-2语义挑战 | 干净上下文，只给主张和证据 | 同会话接管必须标记独立性下降 |
| PoC角色 | 打包既有验证证据 | 不重新验证或定级 | 环境不可用时`inferred` |
| 修复生成角色 | 生成补丁/提案 | 不能自我认证修复成功 | 验证/复核不足写缺口 |
| 独立修复复核角色 | 检查绕过和合法行为 | 与补丁生成上下文隔离 | 不可用时不能写完全通过 |
| 报告投影角色 | 只读投影上游事实 | 不新增安全判断 | 错误返回字段所有者 |
| 知识演进提案角色 | 生成晋升/弃用提案 | 不得自行批准 | 只有人工`approved`可写库 |

逻辑角色不等于每个能力都启动一个物理subagent。只有并行或独立性有真实价值时才派发。
