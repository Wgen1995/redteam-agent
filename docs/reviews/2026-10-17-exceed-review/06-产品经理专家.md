## ③ 差距（照实骂）

**③-1 最大讽刺： 「授权目标进」是产品第一身份，UI 建战却走伪造授权。** 产品定义第一句就是「授权目标进」（tanyin-product-v1.md:6），账本 add-goal 本来有授权四件字段，但 webui 建战直接 `--allow-missing-auth=1`，auth-doc 填 `AUTH-WEBUI-N.pdf`、auth-sha256 用「名称+时刻」指纹现造、有效期自动+7天（server.py:516-520 实读，注释自白「授权四件=场景占位」）。**银行级防篡改账本，郑重记录了一场没有授权书的战斗。**这不叫捷径，这叫产品身份自伤——ARTEX 建 task 至少不伪造授权文件。这道豁免通道每多活一天，「每个漏洞必须实证」的牌子就被自己的建战表单打一次脸。

**③-2 浏览器能建战不能开战，D4 兑现度三分之一。** 用户怒斥「界面就是垃圾……我们零按钮=零产品」（USER-CHARTER:17），方向盘批立了五按钮，落地结果是： 建战✅、暂停/急停✅、介入✅、审批✅、下载✅——**唯独没有 launch**。CTRL_ACTIONS 三元组（server.py:95）里没有点火。表单里「创建后立即执行」是 disabled，页面自己印着「后端未接线，本次提交不生效」（new.html:270、:284）。**四个字段画在界面上骗眼睛，这就是用户骂的「看得见的完整设计」的反面教材**（USER-CHARTER:18）。要么接线要么砍掉，摆设字段比没有字段更毁信任。

**③-3 正门在产品文档里不存在。** D4 说「全程浏览器」，README 四种运行方式全是 CLI（README.md:33-72），webui 起法只活在 HANDOFF 工程日志里（HANDOFF.md:1403）。一个新用户 clone 下来，按文档走永远发现不了 9 页界面和方向盘。**产品把自家正门藏在交接日志里，这不是低调，是文档残废。**

**③-4 无 LICENSE＝零定价形态＝别人连「能不能用」都是未知数。** 五家最差的 ARTEX 至少有 AGPL+禁令（明确告诉你不能用），我们连这一行都没有（根目录实测）。02号评审 P0-5 已挂呈批。**没有许可证之前，「超越五产品」在任何对外意义上都不成立——你不是一个可被采用的产品。**

**③-5 复测是客户旅程的终点，我们是空白。** 一人红队接活的完整闭环是「打→报→客户修→复测证明修好了→收尾款」。pain-points 把「复测回归成本高」列为一人红队 14 痛点之一（pain-points:35，全行业只有 paranoid 一家有自攻击复验）。我们有战内重放（P4 门，30/30 VERIFIED），**但没有跨战复测**： 上一轮 findings 进下一轮、只打旧洞、出「修了3个/剩2个」对比报告——03号评审 P0-4 三命令躺着。UI 更是一个复测入口都没有。客户问「修没修好」，我们答不上。

**③-6 无客户实体： 一人红队接第三个客户时数据就成一锅粥。** 战斗平铺 battle-N（~/.tanyin/battles 实测），报告无客户名无编号。用户画像是「一人红队」，但一人红队的工作单元是**客户委托**不是战号——给甲方的报告里混着乙方的资产名，这在渗透交付里是事故不是不便。ZhuLong（用户自己的另一个平台！）都有项目+敏感标记+成员三层（zhulong:63-65）。**给五家垫底的东西在我们自己的生态里都有现成答案，却没抄。**

**③-7 报告内容五家最硬，形态五家最糙。** 「渲染不造数据+时间链断言+未verified禁宣称」（report_render.py:1-30）是代差级内容质量。但输出物： 无封面、无客户名、无报告编号、无密级、无版本页眉、纯内部格式。ARTEX 至少把报告当「一等公民页签」渲染（artex:271），ZhuLong 有下载中心。**我们的报告拿去投标，第一眼就被格式扣分——内容赢了，门面输了。**

**③-8 合规输出=占位常量。** 「等保段=常量文本，R11 法务过审对象」（report_artifacts.py docstring 自注）。ZhuLong 有 227 条合规规则进知识图谱（zhulong:88）。审计转岗/中文合规报告是一人红队 14 痛点第 8 条（pain-points:39）——这是目标用户的钱袋子需求，我们只留了个占位符。

**③-9 通知为零。** 战打完了、审批待办了、预算烧 80% 了——用户不知道，除非正盯着浏览器。ARTEX 六渠道推送是地板（artex:545）。对「无人值守自主渗透」定位的产品，**没有通知等于自主性打折**： 你敢让战士打 8 小时，是因为打完会叫你，不是因为你要每 10 分钟看一眼。

**③-10 文档厚度 3 成。** CSAI 34 篇专题文档+multica 128 版 changelog 是「产品化纪律」的证明。我们 130 行 README 里连自家 9 页界面都不提。且无 CHANGELOG——v0.9.8 加了方向盘这种用户可感知大事，用户没有任何地方能看到「这版更新了什么」。

## ⑤ 我们独有优势（五产品都没有的）与放大法

**⑤-1 「整个目录=交付物」+客户可自行验真——五家无一能及，放大法是把它从 README 一句话变成产品仪式。** 客户拿到报告目录，自己跑 `python3 cli/tanyin-ledger verify-chain` 就能验证报告没被改过（README.md:93-101）——ARTEX 的 PostgreSQL 可变库、VulnClaw 的无链 jsonl 都给不了（corpus-audit:32、:106）。**放大法三步： ①报告尾页印「验真三步」自助命令（把哈希链翻译成人话： 改任何一个字，链就断）②webui 报告页放「在线验真」钮（验给客户看，不是讲给客户听——CHARTER 条15 图律的交付版）③对客户出验真一页纸**。这是把技术代差翻译成客户可感知的差异化——07 号叫价值翻译，产品侧的落点就是这三件，~80行+报告尾页文案，半天。

**⑤-2 双面同源（UI 写路由全走 CLI 子进程）——把架构事实升级为产品承诺。** server.py 的 7 条写路由全部 subprocess 调 CLI 命令面、零账本直写（server.py:358-377）——「一套账本两张脸」在代码层是真的，ARTEX/CSAI 的 UI 都是专属 API 缝合体、VulnClaw 四外壳各自为政。**放大法： 立 UI/CLI 行为一致钉测（parity test： 每条写路由断言其 CLI 子进程调用参数与手工命令字节级一致），然后把「界面做的每件事，终端都能一字不差重演」写进手册——这是双面一等公民最硬的兑现证据，~60行测试，半天。**

**⑤-3 度量页（召回曲线/对照实验）——客户可见的「越打越强」。** 13 战召回曲线+McNemar 是五家唯一的效果度量面（corpus-audit:34/53/71/89/108 五家全无）。**放大法： 报告附录自动带「平台历史召回曲线」（脱敏聚合），客户每买一轮服务都能看到工具在变准——把度量环从内部质量工具变成销售素材。**~100行（metrics 投影复用），1天。

**⑤-4 零依赖 clone 即用——把安装优势做成演示优势。** ARTEX 要 PG+Docker，我们要 git+python3。**放大法： `tanyin demo` 一条命令——自带靶场干跑→生成样例报告→浏览器打开结果页。新用户 15 分钟从 clone 到看见第一份带哈希链的报告，胜过一千字文档。**~150行（干跑模式+样例数据已存在，README 方式4），1天。
