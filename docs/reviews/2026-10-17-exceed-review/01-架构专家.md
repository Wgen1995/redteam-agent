## ① 现状: 家底盘点(全部带出处,只列实建,不列蓝图)

### 1.1 总架构: 一份内核三扇门 + 五层结构

- **三扇门共用同一个 AI 战士+同一套账本纪律,唯一区别是监督员是谁**: 门A 直接对话(人当看门狗)/门B 引擎托管(Python 看门狗)/门C 靶场练兵(看门狗+评分器)。出处: docs/design/architecture-map-v3.md:9-19。
- **五层分工**: 看门狗层(保活,不碰战术)→判据层(账本,管跑得真不真)→AI 指挥层(管下一步打什么)→度量飞轮层→分发与引擎总线层。口号是「战术归 AI、判据归账本、保活归 Python——三层互不越权」。出处: architecture-map-v3.md:21-50。
- **一句话总纲**(原文): 「AI 能骗过的只有人,骗不过这三层;而人只出现在 P5.5 签发门。」出处: architecture-map-v3.md:160。

**架构评语**: 这个分层是干净的真分层,不是 PPT 分层——每层有独立代码、独立测试、独立失效模式。五家里没有任何一家把「判据」从「执行」里拆出来过(ARTEX 的 planner 既定方向又记账、VulnClaw 的 solver 既决策又写账)。这是我们的骨架优势,后面第⑤节展开。

### 1.2 账本(判据层): 13 表 TSV + 哈希链——实建、实测、实战在册

- **13 表清单**(战前 goals/scope/creds/approvals + 作战 assets/facts/intents/findings + 判据 timeline/edges/matrix + budget + E-index): contracts/01-ledger-schema.md §2 总表清单,13 行逐表在册。
- **timeline.tsv 是第一事实源**,链式哈希,全部 13 表可由 timeline+提交文件确定性重建;写前拒收(畸形行 REJECT 不部分写入);ID 由 ledger-next-id 原子分配,子代理/引擎无铸造权。出处: contracts/01-ledger-schema.md:8-17。
- **实战验证**: 「账本完备 13 表 322 行」(battle-4 实战验收)、13 战逐战 verify-chain 全 PASS、ARTEX 五路深读交叉确认「哈希链——我们已有而它没有(2 路 grep 证实)」。出处: docs/research/corpus-audit-research.md:123。
- **计分铁律**: 发现计分四条件=active+端点对得上+证据卡重放验证+信标词在卡,烂帐=0 分(b25 的 54 发现只计 32)。出处: architecture-map-v3.md:96。

### 1.3 看门狗层(门B 韧性): 单战士监督已是五家最强档

- 机制清单(全部实建): 心跳 30s / 分级击杀 3min 软+8min 硬 / 重启指数退避 30s→2m→8m 封顶 / 战中指令注入(directive 文件 digest 变化→带令续跑) / 预算执法(30s 快照+超限收尾令) / LOGONLY-ALIVE(账外气味照亮不击杀) / ask:human WAIT 停表通道 / caffeinate 防睡+通知+launchd 模板。出处: architecture-map-v3.md:112-124;代码 cli/tanyin-runner(main 函数 166 行起,relaunch/budget/logonly/wait/caffeinate 全在)。
- **实战证据**: b24 断网三度点火零账损;b27 82 分钟无人看护 0.70;op-1 门A 0.70 单样本峰值。出处: architecture-map-v3.md:19。
- **信任根(v0.9.6 S1)**: 战士进程 env 白名单(密钥类变量物理不可达,真子进程 kernel 级实证)。出处: architecture-map-v3.md:196;cli/tanyin-runner:43-47(WARRIOR_ENV_ALLOW 单源)。

## ③ 差距(照实骂)

### 骂法先说结论

**架构竞争力总分: 6 成。** 拆开: 审计/执法/真值 9.5 成(五家无人能及)、单战士韧性 8.5 成、CLI 面 8 成、升级演进 7 成、多战场并发 4 成、常驻引擎 3 成、分布式 2 成、治理/调度 2 成。**我们是一根极硬的脊柱长在一条还没长出来的腿上**——判据层世界级,执行编排层还停在「一个保姆看一个娃」。

### 骂点逐条(按疼度排序)

**G1|「常驻引擎」三个字我们现在没资格说。** ARTEX 的引擎是事件驱动的: worker 一写回图,planner 立刻醒,防抖合并,过六道门,派新意图——这是一个活的循环系统(engine-parts:79)。我们的 runner 是轮询 30 秒的保姆,战士死了拉起来,别的什么都不懂(architecture-map-v3.md:112-124)。v1.0b 常驻循环还在路线图上(map:155「v0.5 引擎接线」一行至今未勾)。**更丢人的是: 前一轮架构评审(F1-F10)把该说的全说透了,三周过去了,最要命的地基批(O(1) 追加)还在「排队」**(map:206)。我这次亲自读了 cli/ledger/timeline.py:30-40——append_tl_locked 依然是「读全表→算链→整文件重写」,一次追加成本随账本行数线性涨。上一轮实测 2000 行 36ms、十万行约 1.8 秒,还零竞争(docs/reviews/2026-10-15-direction-review/01-arch-autonomy.md:43-52)。常驻循环=事件量从战级 400 行推向无上限,**这颗雷不排,v1.0b 开工就是自爆**。

**G2|多战士并行的宪法答案躺在仓库里五周没人领。** contracts/01+07 白纸黑字: 「规划者=唯一写者,战士=子代理只产 submissions,验收后落账」(contracts/01-ledger-schema.md:14;01-arch-autonomy.md:27-29)。现在的现实是每个战士都被 SKILL.md 注入「总控人格」——N 战士=N 个自认唯一写者,互相 REJECT,状态文件互吞(01-arch-autonomy.md:31)。**intents 表没有属主、没有租约**(01-arch-autonomy.md:98-100): 战士认领后暴毙,意图永久卡 active,收敛判定失真。这不是「待开发的功能」,这是「答案已印好没发卷」——比没答案更丢人。

**G3|「多战场并发」是目录隔离撑场面。** webui 能列战斗、能建新战、能切换(server.py:15-16 的 ?battle=N),但: 无战斗注册表(运行中/暂停/排队状态机)、无全局并发闸、无资源上限、无队列调度。ZhuLong 一个调度台该有的 claim 环/心跳/宽限/孤儿恢复/优雅停机梯,我们一件没有(zhulong 手册:73、110-116)。同时开三战会发生什么?三个 runner 各自为政,谁也不认识谁,共享的本机出网带宽和 LLM 配额没有任何仲裁。**「登录多战场」写在 v1.0b 路线上(tanyin-product-v1.md:18),但架构上连多战的资源模型都没人写过一页。**

**G4|治理层是白板,而 CISO 评审第一问就打在这里。** 单操作员、单口令登录(server.py:449-468)、无角色分离。multica 有 owner/admin/member+每成员可跑哪些 agent 的精确授权(engine-parts:57);CSAI 有平台 RBAC+资源归属(engine-parts:153);连 ZhuLong 都有三角色。**渗透测试工具的天职是「谁批的、谁打的、谁看的」三分**——我们有全场唯一人工触点 P5.5 签发门+HMAC 持钥审批(这是好牌!),但签发人只有一个身份位。审计员、批准人、操作员在账本里不分家,企业采购评审过不了职责分离(SoD)这一关。

**G5|战士跑在操作员全权用户态,隔离故事讲不出口。** env 白名单(S1)管的是「密钥够不着」,不是「战士干不了坏事」——战士进程仍能读操作员家目录、写任意文件、起任意进程。ZhuLong 有一次性容器沙箱+出网管控+凭据注入+五类孤儿清扫(zhulong 手册:116);ARTEX worker 至少被 MITM 代理全程录制;CSAI 有 toolguard 正则+WebShell 隔离域。我们对外讲「四层执法」时,对面 CISO 问一句「战士进程本身呢?」——现在只能摊手。egress 代理(Tier3)是唯一硬隔离件,但它是网络向的,不是系统向的。

**G6|schema 演进只有版本号没有迁移路。** 全表带 schema_version=2,v3「推迟至首个真实列集变更」(2026-09-27-b8-discovery-notes.md:32)——推迟不是问题,**没有任何迁移工具/流程/先例才是问题**。13 表是纯追加+事件溯源,天然适合机械迁移,但「链上历史怎么办」(重锚还是附迁移事件)这个政策没人裁定。企业问「你们升级会动我的历史账本吗」,现在没有机检答案。

**G7|双面一等公民,CLI 面欠两笔小账但致命于可信度。** ①退出码: VulnClaw 连「0=干净/1=事故/2=有已验证发现/3=仅候选」都契约化了(corpus-audit-research.md:108),我们 49 条命令的退出码语义靠人读源码;②结构化输出: 无全命令 --json。要让 ZhuLong 这类调度台、CI、脚本放心地驱动我们,这两笔是入场券。③tanyin serve 一条命令起服务至今没收口(USER-CHARTER.md:8 红字挂账中)。

**G8|观察面画布在航,但「活运行面」的架构位还没钉死。** 攻击路线画布(缩放/小地图/节点卡)在做(map:204),11 类节点词汇已获用户原话认可(父代 2026-10-17 锚点:「不断渗透图谱不断演变」=图谱是活运行面不是静态视图)。但架构上 graph 查询三命令(graph-neighbors/graph-paths/graph-horizon,graph-driven-ops.md:10-13)目前只喂 P3 派单,**还没成为两面的统一作战面**——Web 画布点节点不能派单,CLI graph 输出与画布无同一契约。ARTEX 双图是给它自己引擎用的,我们若把活图谱做成「人机共用的指挥面」,才是超越;现在只做了一半。

### CISO 采购架构评审模拟(直接回答任务问题)

**能不能过: 单工具采购能过,平台级企业评审现在过不了。**

能过的部分(且是碾压级): 证据链(哈希链+重放计分+四要素证据卡)、范围执法(四层+egress+金丝雀+scope 空 422)、凭据治理(vault 占位符+双流脱敏+密钥物理不可达)、人工签发门(HMAC)、确定性重建、供应链锁定(tools.lock)、报告守门声明。**这套「审计叙事」五家没有一家拿得出来。**

过不了的部分,评审官会问五问,我们现在答不上:
1. 「操作员和批准人能是同一个人吗?」——现在是(G4)。
2. 「AI 战士越权动我内网别的机器怎么办?」——网络向有 egress 执法,系统向无隔离(G5)。
3. 「同时跑五个项目怎么管?」——没有并发闸和资源模型(G3)。
4. 「升级会改历史审计记录吗?」——没有迁移政策(G6)。
5. 「机器挂了/账本丢了怎么办?」——有 git 推史先例但无备份/恢复/保留策略的成文承诺。

## ⑤ 我们独有优势(五产品都没有的)与放大法

### 优势一: 哈希链账本宪法+确定性重建——五家全败位,我们 9.5 成
ARTEX/CSAI/multica 全是可变数据库零防篡改,ZhuLong 人工终审(确认率 8%),VulnClaw 无链无单写者(corpus-audit-research.md:32/51/69/87/106 逐家实锤)。**放大法**: ①做「第三方验证包」——交战导出+一个不依赖我们代码的最小 verify 工具(链校验+重放抽验),让客户审计员**不需要信我们就能验我们**,这一招五家都接不了;②把「ARTEX 51 findings 全 pending 无一复现」(corpus-audit-research.md:38)与我们「烂帐=0 分+30/30 重放」做成对照页,进报告模板固定段——已证的差距要摆在客户脸上。

### 优势二: 执法在机械层,不在提示词层
ARTEX scope 自扩打穿评测网络(实测)、CSAI「不得质疑授权」写在 prompt(engine-parts:122)、multica「授权八问」纯 prompt 级(multica-source-study.md:140)——我们是账本 REJECT+guard 三态+egress 强制 env(ACL 坏=fail-closed 拒启动)+金丝雀+密钥物理不可达。**放大法**: 每战报告的「执法层清单+拦截计数+金丝雀结果」守门声明已有(铁律 5),再进一步: webui 加执法活仪表(拦截流/金丝雀状态实时可见)——**把「我们敢让 AI 自主打」的底气变成客户能实时看见的东西**。

### 优势三: 度量飞轮+统计判决——全行业没人给自己出考卷
双臂 McNemar、预登记纪真律、13 战基线、p 值进账(architecture-map-v3.md:147-154 三层纠错链)。五家全部「无效果测量」(corpus-audit-research.md:34/53/71/89/108)。**放大法**: 把同靶场同 GT 的「引擎对比考卷」产品化——我们自己的度量页已经是雏形,下一步把 ARTEX/VulnClaw 当被考引擎接进靶场对跑(8-fork 已提同场对比缺口,corpus-audit-research.md:170)。**谁出考卷谁定标准——这是架构位的胜利,不是功能的胜利**。

### 优势四: 一份内核三扇门+插槽制——形态光谱里的唯一生态位
ARTEX 13 万行 Go 单体是负债不是资产(absorption:36 明判);我们的骨架自持+冲程可换(工具/skill/循环/引擎/宿主/模型档全插槽),「模型档次变成可替换参数而非产品命运」(absorption:46)。**放大法**: ①P1-4 把第二个引擎真插进去——插槽制的全部信用在于「真的换过一次」;②slot 契约版本化(引擎 manifest/宿主模板/工具卡各带版本+兼容矩阵),让「可换」从口号变成 selfcheck 绊线;③五宿主安装器把「装到哪」的答案从 3 家扩到 5 家(Claude 模板半小时量,map:132)。

### 优势五: 活图谱(11 类节点词汇,用户原话认可)——「不断渗透图谱不断演变」
用户锚点(2026-10-17): 8900 攻击路线画布的 11 类节点词汇(起点/目标/意图/事实/漏洞/提示/压缩/派生/意图链/产出/证明)获用户原话认可,账本+图谱演进保持该词汇;图谱=活运行面,不是静态视图。ARTEX 双图强但只喂自家引擎,人看不见;ZhuLong 知识图谱是静态规则库(corpus-audit-research.md:70)。**放大法**: ①词汇冻结为契约(进 contracts/,版本化,不许漂移);②P1-6 落地「图上派单」——画布节点卡直接产意图,graph-horizon 可达集×矩阵空格喂派发排序(graph-driven-ops.md:14-17 设计已在册);③图谱查询 API 双面同源(CLI graph 三命令与 Web /api/graph.json 同一投影)——**人机共用一张活的作战地图,五家没有一家做得到,因为我们唯一拥有「图=账本投影,零额外状态」的地基**。

### 优势六: 全场唯一人工触点(P5.5)+HMAC 持钥签发
五家要么无人工门(VulnClaw 上游全开)、要么人工门无处不在(ARTEX 37 条审批、ZhuLong 全人工终审)。我们一个人工触点、位置在终局、持钥可验。**放大法**: P1-1 角色三分后,这个触点变成「批准人」角色的全部工作面——审批卡+预算卡+报告签发三合一,把「人只做决策」(USER-CHARTER 第6条)做成产品的招牌交互。

## 结语(一句话判决)

**方向对、脊柱硬、腿没长。** 判据层(账本/执法/度量/真值)是五家加起来都没有的东西,一根极硬的脊柱;但常驻引擎、多战并发、治理分层这三条腿还停在路线图和「排队」里。CISO 评审单工具能过、平台过不了。P0 六件事 18-27 天清完,腿就立住;P1 七件事再清,企业评审五问全有答案。**超越五产品不是补齐它们的长处——是把它们的长处(ARTEX 的循环/multica 的组织/ZhuLong 的调度/VulnClaw 的 CLI 契约)插进我们的插槽,同时让它们永远够不着我们的账本宪法。**

*本评审写入物仅此一件。全程只读语料与代码;测试套件为只读执行。*
