## 三、差距（照实骂）

**骂 1 · 05 评审 14 项修正方向,两个评审周期还债数=0,同期功能照加不误。** 逐条验尸（详见⑥对账表）: 撕裂快照、SourceFileLoader、lint/coverage、枚举单源化、rc 分离、timeline O(1)、idor/token- 垃圾、vendored 污染、webui 读降载、测试分片——**一项没还**。同期 git log（10-15→10-17）: 方向盘批+37/26/20 测、攻击路线画布、四份研究档、宪法补律——**借新钱的速度高于还旧债的速度,knowledge.py 还长了 126 行（1332→1458）,测试时长 378.7s→432.5s（+14%/2 天）**。「由本批顺手驱动,不由哪颗先炸驱动」的病,05 评审已确诊,现在是三期:不是不知道,是没人把还债排进批次——05 评审原话「这正是病本身」,我原样再念一遍。

**骂 2 · 指挥面已经上线,操作员脚下的数据地板还裂着。** webui 已从「观察面」升级为「指挥面」（暂停/急停/审批/开战七个写端点）,而读侧仍是 Session.__init__ 无锁串行载 13 表（cli/ledger/core.py:113-121）、每 /api/state.json 全量重建 Session + cmd_status 再读一遍 timeline（cli/webui/snapshot.py:55-67）、无 epoch 戳无重试验证（grep 实测零命中）。写端点越多、操作员越信这个页面,**在撕裂窗口上按「急停」的概率就越大**。这不是显示层小 bug 了,是安全事故的温床。30 行的 epoch 戳拖了三个评审周期。

**骂 3 · 公开仓没有 LICENSE。** 仓推在 github.com/Wgen1995/redteam-agent 上,任何第三方 clone 后法律上「保留所有权利」。企业级三件套「能装能跑能升级」的前置是「能合法用」——**这是 0 行代码、半天工作量（选型+文本）的地板,拖到现在没铺**。五家里 ARTEX 用 AGPL+学习禁令把商用门焊死、multica 设付费墙,都是许可当武器;我们连武器都没领。

**骂 4 · 版本纪律在自我否定。** 命令面计数三处三个数:41（cli/tanyin-ledger:3 docstring）、44（cli/README.md:3）、49（真相,registry 6 模块+入口挂载 zhulong_export）;cli/README.md:50 写「181 单测」（真值 1605,差 9 倍）;python 地板三口径:3.9+（ADR-P3/cli/README.md:70）、3.10+（README.md:18）、CI 只测 3.11/3.12;--help 退出码 2。一个把「退出码分域」当招牌的系统,自己的 help 都站错了域。

**骂 5 · 无 lint/无类型检查/无覆盖率,低于 VulnClaw 地板。** VulnClaw 好歹有 pytest+CI+doctor;我们 CI 四矩阵跑得很勤,但**检查器是零**——mint_wall_sync 型漂移（HANDOFF 在案: _append_event 增必填 ts 后 3 参调用 TypeError,靠战士运行期举报才发现）在这种 AI 高速生成代码的工作流里是结构性风险,mypy 是静态期一秒抓的事。ruff/mypy/coverage 是 dev 依赖不进运行时,**不违反零依赖律——把产品选择伪装成语言约束,05 评审骂过一遍,原样成立**。

**骂 6 · 测试串行 432 秒且每两天涨 14%,CI 无分片无 macOS。** 全量本地跑一遍 7 分钟,反馈回路越来越钝;CI 矩阵里没有 macOS——**开发者的主力机不在被验证的平台清单里**,launchd/caffeinate 这些 mac 专属件全靠手测。VulnClaw 的教训摆着:macOS 无 GNU timeout 这类平台坑是实机才炸的（vulnclaw-live-trial §1.2-4）。

**骂 7 · 「tanyin serve 一条命令」是产品形态 D4 的钉死承诺,至今没兑现。** 现在起界面要 cd cli && python -m webui.server --ledger-dir D（server.py:37-38）——「clone 即用零依赖→serve 单命令→口令登录→全程浏览器」四步里第二步缺位（USER-CHARTER #3 标 🔴 的三条之一）。CLI 面给人类的件（--version/--json/补全/man）同样为零:**我们的 CLI 是 AI-first 的,人类一等公民这半边目前只存在于 webui**——这正是双面硬约束要纠正的偏科。

## 五、我们独有优势（五产品都没有的）与放大法

1. **供应链锁定链（tools.lock 8 键 ECDSA + 引擎插槽启动先验签 + 模板逐文件哈希）**。五家全部为零:ARTEX 依赖闭源 norma SDK,VulnClaw pip 装啥是啥,CSAI vendor 7 库,multica 三容器镜像。**放大法**: 把它写成企业级卖点第一页（「渗透工具跑在客户机上,每个工具每字节可验签」——这在甲方采购问卷里是独分题）;给 VulnClaw 插槽试用已合格的先例（WGEN001 通道,vulnclaw-live-trial §10）套同款验签流程,第三方引擎接入即继承供应链纪律;生产钥仪式（install/KEY-MANAGEMENT.md）从 TEST-ONLY 升真钥时,顺便做一次公开可复核的签名轮换演练——这本身就是营销素材。
2. **1,605 测+59 金样字节级+selfcheck+evals 双套件进四矩阵 CI,全绿亲验**。VulnClaw 1,680 测函数量近但无金样字节级、无静态一致性门;ARTEX 无效果度量;CSAI 41 前端测。**放大法**: ①金样+仿真挂性能阈值=血压计（P2-17）,质量资产变监控资产;②把「测试数/金样数/CI 矩阵」做成 webui 关于页的固定质量声明——企业买家看得懂的信任信号;③测试分片后把「每 PR 全量绿」写进贡献纪律。
3. **哈希链账本=升级与审计的双故事**。timeline 第一事实源+state-rebuild 全量重建:竞品的 PG/SQLite 可变库做不到「升级即重放、断电即重建、篡改即报警」三合一。**放大法**: P1-14 升级 runbook 把它讲成人话;报告守门声明（设计 §0.3-6）里加「账本可全量重放验证」一句,让每个交付报告自带防伪背书。
4. **一核两面的单一写路径（webui 写=subprocess 调 CLI,零账本直写）**。这是 VulnClaw「四外壳共用 AgentCore」的更严版本,也是双面一等公民的工程学答案:**面可以无限加（webui/TUI/JSONL 协议/DSH 插件）,写路径永远一条**。**放大法**: 把这条写成显式工程铁律入 SYSTEM-MAP（「任何新面必须经 CLI 契约,违者 selfcheck 红线」）;P1-12 的 --json 契约一旦落定,新面接壤成本降到「读 JSON」一级。
5. **跨平台字节纪律+Windows CI**。.gitattributes 全类型钉 LF/入口 UTF-8 重配防 GBK/.cmd 双胎/windows-latest 进矩阵——CSAI/multica 都没把 Windows 当一等平台。**放大法**: P1-11 补 macOS 后,三平台 CI+五宿主矩阵=分发面最宽的合规故事;给企业 Windows 主机客户出一份「离线安装包」制作脚本（zip+tools.lock+release.pub,零网装）。
