## ③ 差距(照实骂)

**1. 最大的差距不是设计,是「设计定稿三十天、代码零行、五接口零裁决」。** E6 在 10-15 把五个接口逐个点名(06-whitebox:16):①桥用什么边型 ②sink 进哪本账 ③矩阵怎么扩 ④调度激励 ⑤车道 A 确定性三软肋。今天(10-17)逐项复查代码:**anchor 边不在十边枚举里(write_cmds.py:107-118)、engine-hyp 不在 kind 枚举里(:103)、矩阵胞态还是四值(:1032)、partial 不在意图状态里(:541)、YAML/方言/解包三裁决不见任何修正案**。同期我们干了什么?黑盒侧方向盘批、视觉工艺批、VulnClaw 插槽试用、九页观察面——全是该干的,但白盒是用户 10-15 亲口点的重设计令(recovered 文件四条原话),是「渗透时可能有 API 文档/源码/安装包」这个真实作战需求的唯一承接,**它现在全部活在纸面上**。再骂一遍 E6 那句:不裁决就动工,每一条都会被实现者用最顺手的方式悄悄定掉,而最顺手的方式恰好都是错的那种。

**2. 激励漏洞是结构性炸弹,不修=覆盖律变话术。** E6 F2 的推演(06-whitebox:57)今天依然成立且无人认领:规划者优化「预算内结算 recall」;深挖 band0 sink 卡=高成本高风险;否证=零信用;不开卡=deferred 合法不扣分。理性策略=「不开卡就不会输」。E4 修正案 D 把「engine deferred=0 进 P4 收口判据」写进了档(tanyin-product-v1.md:39),但**账本层面没有任何机械执行这个判据的东西**——deferred 状态连触发条件/到期重开都没有(A7 处置七值+review_expiry 的语义先例在册未接,06-whitebox:134)。GenSift 拿 stop hook+L1 单调性+完成计数死守的分母,我们打算用三个还没写的参数守。

**3. 确定性三软肋拖一天,「确定性」三个字就虚一天。** 纯 stdlib 律 vs OpenAPI 主形态 YAML 只能活一个——这是修正案级别的取舍(E6 三问之二原文:「拖到施工时会被某个实现者用 import yaml 一行代码悄悄替你们决定,然后零依赖律从宪法变成备忘录」,06-whitebox:142)。ERE→Python re 的方言迁移+ReDoS 新增风险、解包三帽+路径归一+子进程 RLIMIT——判据在 vuln-agent 资产里有现成页(zip-bomb/redos-check,06-whitebox:133),没人翻。**还有一条 E6 没骂够的:Python 3.9 已 EOL,安全平台钉死一个不收安全补丁的解释器解析攻击者工件——这本身就是白盒车道的暴露面**(06-whitebox:74 提了,修正案 B 只给了 Go 边车触发器没给 Python 升版,路线里没有 3.11+ 升版批次)。

**4. 输入面缺两件:架构图、产品文档。** 用户原话五件输入(recovered:3),修正案 A 只接了三件。架构图(哪怕是 mermaid/文字版)是「资产图程序挂载」的天然种子——用户画了拓扑,我们直接种成 assets+edges;产品文档是端点字典和业务流假设的来源。这两件不接,「输入面=不止 web」的用户令只兑现了 60%。

**5. vuln-agent 遗留适配器是颗反向地雷。** engines/vuln-agent/adapter.py(175 行)+MANIFEST 还挂在引擎总线表上「在册未接线」(architecture-map-v3.md:137)。它是旧路线(外接八段管道、md 正则归一化、findings 直出 confidence=C2/C3)的产物——**与「引擎不产发现产假设」的新宪法直接冲突**(engine-fusion.md:6-9)。不裁决它的去留,某天某个批次就会有人「顺手把它接上」,然后引擎产物直入 findings,精度门当场穿孔(engine-fusion.md:54 的防退化钉「engine-hyp 直入 findings=selfcheck 红线」还没写)。

**6. 白盒的双面=两面都是零。** 双面一等公民的新约束下,白盒今天 CLI 面没有一条命令(tanyin-ledger 49 命令里没有 parse/unpack/scan 族)、界面面九页里没有一个白盒像素(热图/十边图/证据卡都只消费黑盒产物)。黑盒侧「一核两面」的架构(8900 写路由全经 subprocess 调 CLI,模块零账本直写)已经把路修好了——白盒只要落在账本上就免费继承两面;但反过来,**白盒若只在引擎侧轨内存里跑、不入账,两面就都看不见**,这正是 E6 F4 警告的「sink 只活在引擎内存/导出文件里」那个更糟的分支。

**7. 实验设计还没吃 E4 的修正,第一个被错尺错杀的就会是车道 B。** E6 F6(06-whitebox:110-122)说得很清楚:死区 13 题的三大归因(凭据链/载荷形态/结构投放点)恰好全是源码可答的——白盒的真实效应住在 post_auth 死区救回里,全量池化会把效应稀释进送分区;「p=0.25→白盒无增益→砍车道 B」的剧本是照着这个结构写的。而且**死区 14 题逐题判「源码可答/不可答」是零战成本的先手**(13 战 per-GT missing 明细+归因都在盘上,06-whitebox:115),到今天没人做——这件事半天就能干完,它同时决定车道 A pattern 语料的工程优先级与实验样本量。

**8. 语料与飞轮衔接是隐性强项,但一样停在纸面。** knowledge/ 已有 VulnClaw 挖来的 8 个 detail-pack(CP-0001..0008,corpus-audit-research §三)、学习卷 VOL-04《源码审计→黑盒联动》整卷成文(入口点优先审计法/代码→PoC 翻译五步/半黑盒安装包,docs/learning/VOL-04-source-assist.md)——这是五产品谁都没有的「白盒→黑盒折算表」方法论。但这些页面今天没有任何一条命令消费它们。GenSift 的 509 条 pattern+1623 个 fixture 在用户家目录里躺着(宪法 #23 只读吸收,USER-CHARTER.md:23),翻译迁移零开工。

## ⑤ 我们独有优势(五产品+GenSift+codex 都没有的)与放大法

**1. 白盒假设×黑盒重放,同一本账闭环——全场独一份,是白盒维度的「越打越准」发动机。** GenSift 的确认器是「另一个 LLM 重读代码」(Confirmer,6-gensift.md:75),codex 的确认是「主审计者独立重验+动态阶梯」(7-codex:60-63),都停在静态/本地复现;五产品连确认器都没有(ARTEX 51 findings 全 pending 无人核,walk-artex-live §4.5)。我们的精度门是**黑盒重放实证**(无重放不计分,engine-fusion.md:6-9)——白盒情报必须翻译成一条可复现请求(VOL-04 整卷就是这套折算表:定位参数→构造请求→绕过输入处理)才算数。**放大法:P0-5 sim 门+P1-4 实验各打一仗,把「源码假设→重放一击即中」做成端到端战例进度量页——这一仗打完,白盒维度的差异化就不再是设计文档里的形容词。**

**2. 哈希链覆盖白盒产物+带 provenance 的锚边——审计域的防篡改是刚需,全场只有我们有。** ARTEX 双图零防篡改、anchor 裸两列无来源/时间语义(2-data-graph.md:32/:37);codex 有 provenance 但无链;GenSift 有账本无链。edges.tsv 自带 provenance 列+anchor 边必填 文件:行+工件 sha256(E6 F1-2 方案)——「这个发现源头是哪行代码、哪个版本的工件」可上链可验签。**放大法:审计专报把「逐发现溯源链(代码行→假设卡→重放证据卡→哈希链验证)」做成固定章节——这是纯代码审计合同场景里五产品谁都交付不出的东西,也是修正案 D 翻案条件(>30% 升一级入口)兑现时的本钱。**

**3. 覆盖律算术化+两本账,机械已在库——GenSift 的覆盖纪律是协议纪律,我们可以是账本执法。** GenSift 靠 stop hook+L1 单调性+exit 1 守分母(协议层);我们已有 submatrix 铸造四条件+防偷扩张(write_cmds.py:1039-1056)、矩阵审计门、P4 收口判据位。加上 P0-3 激励五件套,「全覆盖」三个字从话术变成可计算:冻结分母/追加分母分开披露、deferred=0 才许写进报告。**放大法:度量页「代码覆盖」面板直接消费这两本账——对着 codex 的 coverage surfaces 语义(候选/拒绝/排除/开放问题四态,7-codex:139)抄格式,对着 GenSift 的「没发现必须能解释」抄纪律。**

**4. 单图两域 vs ARTEX 双图分裂——图法上我们以「一」胜「二」。** ARTEX 双图的真值分裂风险(E6 F1:第二张图就是图外状态,违反「账本图谱=渗透的操作系统,无图外状态」立律,graph-driven-ops.md:3)我们天然没有;它的三层可取处(per-kind state 矩阵/覆盖度 CTE/冷压缩)按吸收档抄语义不抄实现(absorption-2026-10-17.md:10「分层记忆→账本图谱单图两域(E6 F1 判决同向)」)。graph-horizon 已实装——sink 卡入池后「图上够得着的高分格先行」的调度协同,是 GenSift(无图)和 codex(无图)都没有的。**放大法:车道 A 产出的 endpoint 资产直接进 horizon 计算,白盒情报即时改变派发排序——这是「渗透内环」定位(修正案 D)的机械兑现。**

**5. 双面底座已建,白盒免费继承——这是对 GenSift/codex 的形态碾压。** GenSift 寄生宿主会话无独立 UI;codex 官方从 GUI 退回 CLI(7-codex:140 自己记录的决策)。我们 8900 九页+方向盘写路由+49 CLI 命令的「一核两面」已在(黑盒侧验证过)。白盒只要落账本,CLI 命令族+界面呈现自动获得同一架构。**放大法:P0-2/P1-1 的每个产出都同时设计 CLI 命令与界面投影(本清单已逐项标注),不许出现「引擎侧轨内存态」。**
