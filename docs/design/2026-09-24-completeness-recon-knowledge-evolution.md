# 完备性设计：信息收集·知识库·持续演进的理论覆盖（批次 4 设计输入）

> 回答三个问题：怎么收才能理论覆盖全部？知识库要装什么才全？怎么保证该演进的不漏？

## 〇、完备性三定律（本设计的地基）

1. **模型驱动**：先定义"资产宇宙"与"测试类型全集"的枚举模型（闭世界假设），收集与测试都在模型定义的空间里进行——**漏=空间里的空格，可见可数可追**。工具只是填充空间的手段，换工具不换空间。
2. **多源法定**：任何维度的一条结论，必须有 ≥N 个独立来源交叉（来源正交：被动 DNS vs 证书透明度 vs 主动探测 vs 内容挖掘）。单源只产生 unverified 态，不产生 done 态。
3. **触发器闭包**：每一类新事实都必须映射到明确的后续策略（再收集/派测试/更新矩阵/登记不动作理由），映射表是封闭目录可审计——**"未消费线索=0"从口号变成可机检的收敛条件**（设计已有的 converge-check 扩展）。

## 一、资产宇宙模型（收集的理论全集）

### 1.1 资产本体（要找的东西的完备枚举）
A1 标识层：根域/子域/通配符记录/短链/重定向链
A2 网络层：IP（v4/v6）/ASN 段/邻接 IP/CDN 节点/防火墙端口面（全端口 vs 常见端口两档，档位落账）
A3 服务层：开放端口/服务指纹/版本/CPE 组件/中间件/框架/TLS 证书（SAN 反推域）
A4 应用层：URL 路径/参数/API 端点（JS 静态分析+swagger/openapi+graphql introspection）/隐藏后台/上传点/回调接口
A5 存储与云：对象桶/数据库暴露/队列/云元数据端点/CDN 源站
A6 代码与物料：前端 JS 包（含 sourcemap）/移动 APK-IPA/API SDK/git 泄露/备份文件/归档快照（wayback）
A7 人的因素：邮箱/账号名/密钥泄露库命中/第三方 SSO 依赖/供应商入口
A8 关联外推资产：同证书/同 whois/同 favicon hash/同 analytics id/同 IP 反查——图谱边外推，界外也记（in_scope=0）

### 1.2 发现通道全集（每个 A 类至少三条正交通道）
- 被动：被动 DNS 聚合/证书透明度 log/whois/ASN 影响/第三方 API（crtsh/securitytrails 类，离线快照也可）
- 主动：字典爆破/置换生成/全端口扫描/协议探测/爬虫跟随
- 内容挖掘：JS 静态分析（端点/密钥/注释）/swagger-openapi/graphql/错误信息泄露/响应头差异
- 历史：归档快照/diff 复扫（时序漂移检测：同源重扫结果进 assets 增量比对）
- 外推：证书 SAN/IP 反查/favicon hash/analytics id 关联
- **侦察金丝雀（本设计新增，机制核心）**：授权范围内**植入已知诱饵资产**（如客户配合埋 3 个冷门子域+1 个非常规端口服务），测绘引擎的召回率=发现诱饵数/植入数——**信息收集的"不漏"第一次变得可度量**（与执法 canary 同哲学：用已知真值自测感知面）

### 1.3 分母就绪门（freeze 前置检查，堵"假全面"）
matrix freeze 前必须过四关：①每资产来源数≥2 或标 unverified+继续挖任务在队列；②诱饵召回率 100%（或披露）；③A1-A8 各类非空或"不适用理由"落账；④外推资产已跑一轮图谱闭包（无未处理悬空节点）。

## 二、知识库内容全集（理论上装什么）

K1 方法论基准库：WSTG/OWASP ASVS/OSSTMM 映射表（版本化）→ matrix 列的来源；项目立项时人工确认裁剪/增补列集（人握方向盘）
K2 打法先例库：跨场脱敏先例页（目标指纹→打法→结论→复盘），开局指纹匹配直接派生任务
K3 Nday 候选库：本地 CVE 快照×CPE 指纹匹配，出 nday-verify 候选（离线匹配，联网仅核验）
K4 工程规则库：deny-list/误报哨兵/白名单基线（已是数据文件，版本化）
K5 技法库（本设计明确化）：按 A1-A8 每类的"收集技法页"（工具+参数+产物格式+失败模式）——引擎实现技法页的机器可执行子集
K6 误报库：历史误报模式→判定引擎哨兵规则的回流
K7 业务模板库：行业化检查单（零售/金融…），biz 标记人工为主的设计边界不变
K8 靶场复盘库：每场仗结束的 retro（什么漏了/为什么/回写到哪类）
**入库纪律不变**：脱敏→机器检查→人工审→四门槛；K5-K8 同走飞轮。

## 三、演进闭环完备性（怎么保证不漏该继续的）

### 3.1 触发器目录（封闭、可审计）
每类事实的策略表（新事实→必经评估）：
asset-added→子矩阵行铸造+关联外推一轮+Nday 匹配；cred-obtained→身份差分候选+权限面复测；scope-amended→矩阵重映射+受影响 intent 重估；fact(unconsumed)→假设风暴五路；finding 证实→同型横向排查（同类资产全量补格）；端口/服务变更→指纹重测+关联 CVE 复查；界外资产→记录不测（不触发收集之外的任何动作，理由落账）。
**审计规则**：触发器目录覆盖全部事实类型；converge-check 增加"未消费事实=0 且触发器目录版本一致"断言。

### 3.2 反漏三件套
①**周期复扫**：廉价被动源定期重跑，diff 出新增即 asset-added 触发（时序漂移不漏）
②**收敛即停止+披露**：全部格子有归属+未消费=0+触发器审计过→停机；做不到就是 budget-exhausted 诚实披露（铁律 3 不变）
③**复盘回流**：每场 K8 retro 必答"这次漏了什么/哪个触发器缺了/哪类通道弱了"——漏掉的东西变成新触发器/新通道/新技法页（知识库消化自身的漏洞）
