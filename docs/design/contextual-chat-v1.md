# 全域锚定对话 设计 v1(2026-10-18)
缘起: 用户令「5产品都看,思路开阔」。调研结论: CSAI/multica=聊天优先范式,ARTEX=任务级留言,ZhuLong/VulnClaw=无;**实体锚定对话=业界空白**。
姿态: 吸收「对话即作业面」(CSAI)+「实体自带线程」(multica),落在我们独有的账本行址上。

## 核心机制: 锚定三件
1. **任意实体可锚**: 发现/资产/证据/图谱节点/矩阵格/任务/智能体——每个详情位都有「问 AI」按钮与右键项。
2. **锚=账本行址**(表+行号+行哈希,graph-realtime 设计已显式化): AI 收到的上下文=该行+血缘祖先+关联证据卡+所属任务阶段,零用户手工粘贴。
3. **对话可派活但必过门**: 从对话发起的动作(重跑该意图/为该资产建侦察意图/复测该发现/改判建议)→ 走审批门+预算帽+执法层,与按钮发起完全同律——**对话不是法外空间**。

## 交互形态
- 右侧滑出对话面板(全局常驻,锚切换=上下文切换,历史按锚分组)。
- 面板顶: 锚卡(实体摘要+行址+「查看原始账本行」链接)。
- 消息流: 人/AI/系统三类气泡;AI 回答带引用(点击跳证据/节点);系统气泡=门卫结果(「已生成重跑意图,审批卡 AP-xx 挂起」)。
- 对话记录=timeline 行(actor=人工/AI,anchor 字段)——**可回放可审计,五家聊天全是状态外旁路**。

## 与既有设计合流
- 任务详情·播报页签(P5.3)=任务级锚的特例;行级重跑(graph-realtime §二)=对话派活的第一批动作。
- AI 对话式建智能体(multica 有)**不抄**: 建执行体=开写路径,必须过授权件(C舰 M4 已判)。

## 接口
POST /api/v2/ask {anchor:{table,row,hash}, message} → 回复流(SSE);GET /api/v2/ask/threads?anchor=… 历史按锚取(timeline 过滤)。
动作派发复用既有: /api/battle/say 指令通道+审批卡,零新写路径。

## 实施量
锚协议+ask API ~200 行 / 对话面板组件(锚卡+引用跳转+系统气泡) ~250 / 派活门卫接线 ~150 ≈ **600 行**,并入 W6 界面线;依赖全在(行址/timeline/SSE/审批门)。
