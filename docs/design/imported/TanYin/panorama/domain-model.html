🗄️ 领域模型 · Graph 范式核心 · session 目录 = 单一事实源

八表 TSV 账本 + E-index + matrix + timeline 构成探索链路图。图谱既是记录（全程可回放可审计）也是推理引擎（未消费 fact 可查询、收敛可计算）。一切状态落盘，LLM 不依赖会话记忆。单写者模式——总控是唯一账本写者，子代理/引擎只产提交文件。

八表账本（TSV · 事件溯源/追加写 · 账本命令是唯一写入口 · 写前拒收）

goals 目标id, target, objective, auth_doc, auth_sha256, signer, valid_from/until, rate_limit, window, emergency_contact, budget, business_context…
结构化授权（授权书 sha256+签署方+有效窗口）+ 预算三元组（token/请求/时间窗）+ 速率上限 + 业务问卷摘要。
scope 授权范围id, kind(include/exclude), matcher, note
授权白名单硬门：支持 CIDR/域名后缀/通配。资产落账命令强制对照本表，界外标记 out_of_scope 且账本级禁止派生 intent——授权边界是机械判定，非 LLM 语义判断。
intents 意图id, title, detail, status, engine, origin, score, via, dedup_key, activation
事件溯源（追加状态变更行）；dedup_key 机械拒重；deferred 激活条件是结构化谓词（field;op;value，命令评估）；blocked 不可自动复活。
facts 事实id, intent_id, kind, target, detail, confidence
kind: port/service/http/info/vuln-clue；落账时即脱敏（凭据/PII 占位符化——运行时数据纪律）。
findings 漏洞id, intent_id, title, confidence, impact, description, reproducible_steps, affected_asset_id, evidence_ids, control_evidence_ids, status
reproducible_steps≥1 强制；两维评级 confidence×impact；control_evidence_ids=差分对照组；合并=supersedes 边+tombstone（不删行）。
assets 资产id, type, value, meta, in_scope
type: root-domain/subdomain/ip/service/app/endpoint/source-code；in_scope 由 scope-check 命令判定（CIDR/后缀机械匹配）。
edges 边id, kind, source_id, target_id, provenance
十种边词汇（见下）+ 来源标注——图谱推理的骨架。
approvals 审批id, command_hash, decision, approver, timestamp, note
审批账本：L3 逐条审批、P5.5 报告签发、P6 知识审批全部落此表；command_hash 绑定原始命令串（审批的是原文，非 LLM 摘述）。
原理逻辑：TSV 而非数据库——零依赖、人类可直接读、diff 友好（决策 6：换 JSONL 不解决状态机/并发问题，SQLite 破坏零代码宪法）。事件溯源（intents/matrix）：追加状态变更行，"取最新状态"是账本命令——追加写与可变状态的矛盾由此消解。写前拒收：每条写命令自带行级校验（列数/枚举/引用闭合/dedup_key 唯一），畸形拒绝写入——校验不晚绑定到 P4。ID 铸造：总控统一铸造 {前缀}-{goal}-{四位序号}，定宽零填充。

原理逻辑：边词汇是受控的（closed vocabulary）——图谱可查询、可校验、可推理的前提是边类型有限且语义明确。「未消费 fact」= 无 derived_from 出边的事实，这个图查询就是 P3 循环的驱动信号。attack 边让攻击链从报告叙述变成可查询路径；cross_ref 边承载跨引擎知识流动；supersedes 让 finding 合并保持 append-only 审计完整。

Evidence 契约（shared/EVIDENCE.md · E-index 索引 + 外置文件）

机制：E-index.tsv 是证据引用单一来源；超长内容外置 evidence/EV-*.md。每条证据：title / observed_at / source_type / source_ref / repro_command（凭据用 {{vault:cred-N}} 占位符——打码与可复现两全）/ repro_kind（single/sequence/concurrent，时序类漏洞引用脚本）/ content_hash 双轨（raw+normalized，归一化去动态字段）/ artifact_path（session 相对，只增不覆盖，重跑另存 -r2）/ pair_group（差分举证组）/ raw_excerpt（脱敏+定长截断）。P4 门禁：hash 命令重算复核 + 全量引用闭合检查。

设计思想：反幻觉 + 可交付 + 差分严谨——LLM 说「发现漏洞」不算数，账本里有可复现命令+内容哈希才算数；对照组证据（证明防护有效的负结果）与实验组共享 pair_group，「已修复」与「被 WAF 拦了」在账本里可区分。凭据保险库（session 内加密文件）解决凭据打码与第三方复现的矛盾。来源：dsh-reverse-skill Evidence 契约 + 审计修订。

两维评级（shared/SEVERITY.md · confidence × impact 正交）

C1 实证复现已在线复现，证据链完整
C2 条件实证原语已证实，利用需条件——必须附条件可达性证据，否则降 C3
C3 风险线索结构性风险/配置缺陷，未实证
➖ 不可利用 / 🛑 已阻断差分对照组证明防护有效——负结果同样入账（回归基线）
impact 高/中/低CVSS 式影响域判定——与 confidence 正交的另一维
设计思想：确定性 ≠ 危害——「我多确定它存在」（confidence）与「它造成多大影响」（impact）是两个问题。已实证的弱密码策略是 C1+低；需内网位置的条件实证 RCE 是 C2+高。压成一维会系统性误导修复优先级（审计修正：原 C1→高危映射是范畴错误）。报告双列呈现+传统等级映射列供非技术干系人。

字段编码与状态机（命令层强制）

编码规范：UTF-8 无 BOM + LF 钉死；字段内禁字面 tab/CR/LF（\t/\n/\\ 转义，命令转义 LLM 不手工）；多值字段 ; 分隔；账本命令参数化（临时文件传参，禁止字符串拼接——目标数据是注入载体，不得进命令层）。

timeline 审计链：每条含 prev_hash+hash 链式哈希——改任何历史行即断链可见；actor 区分总控/子代理/人工；P0 落账 SKILL 版本+文件哈希。

原理逻辑：转义/编码/并发写是文件账本的三大工程雷（审计确认）。解法不是换格式而是命令层强制：写命令统一转义与校验（写前拒收）、单写者模式消灭并发写、链式哈希让审计链防篡改。LLM 只调用命令，不碰底层格式。

session 目录全景

session/<goal-id>/：八表 TSV · E-index.tsv · matrix.tsv（事件溯源）· timeline.md（链式哈希）· state.md（P3 checkpoint/受管重启恢复点）· scope.tsv · approvals.tsv · submissions/<intent-id>/（子代理提交）· evidence/ + vault/（凭据保险库）· report/（签发后）· .gitignore（敏感数据标识+保留策略）

原理逻辑：一个目录=一次测试的全部状态。断点续传与受管重启（重进扫描账本即恢复）、黄金夹具（固定样本规范化比对账本命令输出）、烛龙接入（导入 session 目录即落库，schema_version 协商）都建立在这个「目录即状态」的约定上。
与工程范式的关系：本图是 Graph 范式的落位——结构化数据+关系推理，状态显式建模。八表+十边同时服务于 Loop（未消费 fact 查询驱动循环）和 Harness（TSV 文件任何宿主都能读写）和 Context（状态在盘所以受管重启无损）。
