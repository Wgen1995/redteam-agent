🧭 AI Agent 工程哲学 · Graph / Loop / Harness / Context · 深度分析与架构选型

四支柱不是功能模块，而是四种回答「agent 的复杂性应该放在哪里」的哲学立场。每节六段：哲学立场 → 解决什么 → 架构原理 → 业界谱系 → 代价与边界 → 探隐选型。补立第四支柱 Context Engineering——原设计最弱处恰是三大哲学里没有名字的那一个。

🕸️ 2.1 Graph Engineering（图谱工程）

哲学立场：复杂性放在「状态」里——把世界建模为显式的节点与关系，让推理变成可执行的图查询。状态外置、结构化、可检验。

它解决什么：LLM 的两个根本缺陷——①上下文易失（会话断了状态就没了）；②推理不可检验（说「我分析出 X」但无法审计分析过程）。图谱把「知道什么」和「怎么知道的」都变成磁盘上的数据。

架构原理
· 受控词汇（closed vocabulary）：节点/边类型有限且语义明确——可查询、可校验、可推理的前提。开放词汇=自由文本=回到不可检验
· 图查询即推理：「未消费 fact」=无 derived_from 出边的 fact；「攻击链」=attack 边路径——图遍历可回答，不依赖 LLM 即兴
· 状态外置：agent 的大脑在磁盘不在会话——断点续传、多代理共享、事后审计全部自然获得
业界谱系：知识图谱/RAG（向量检索是软图）→GenCPT 图谱驱动渗透→dsh-pentest 六表模型→LangGraph（类比：图编排，非知识状态外置）
代价与边界：建模成本（不是所有知识都值得结构化）；查询能力受限于词汇表设计；图 schema 错了重构贵——所以词汇表要小而稳（探隐十种边），且 schema_version 要先行（事后加列=全量迁移）。
探隐选型：八表 TSV 账本+十种边（+scope/approvals/E-index/supersedes）。图谱既是记录（append-only 可回放）也是推理引擎（未消费 fact 扫描驱动循环、图邻接推理撮合攻击链、收敛四条件可计算）。图谱收敛=测试完成——把「何时停止」从 LLM 主观判断变成图查询。专属视图：domain-model.html

🔁 2.2 Loop Engineering（循环工程）

哲学立场：复杂性放在「过程」里——不一次规划死，观察→思考→行动→观察的闭环持续演进。计划是活的，随信息增长而重规划。

它解决什么：一次性规划（plan-then-execute）在开放环境必然失效——渗透测试的本质是探索式推理，下一步测什么取决于刚发现了什么。固定流水线（recon→scan→exploit→report）在真实目标面前是削足适履。

架构原理
· 循环体：感知（扫描状态）→ 决策（生成/排序假设）→ 行动（执行验证）→ 落账（更新状态）——每轮状态都变，决策依据永远最新
· 终止条件：循环必须有可计算的收敛判定，否则要么死循环要么靠 token 耗尽这种事故性终止
· 预算控制：假设空间是指数的，必须有打分/排序/淘汰（先验分、top-N 晋升、deferred 池）——「头脑风暴的扩张感」与「工程收敛性」的调和点
业界谱系：ReAct（Reason+Act）→AutoGPT 自主循环（缺收敛判定的教训）→GenCPT 图谱演进循环→o1/R1（类比：隐藏 CoT 循环，非环境交互循环）
代价与边界：循环轮数=成本（每轮 LLM 调用+工具执行）；循环可能震荡（同一假设反复生成——语义判重不可靠，需机械去重键）；无收敛判定的循环是灾难——收敛条件必须与状态模型（Graph）联动，且必须有预算合法终态（预算耗尽≠事故，是显式模式）。
探隐选型：P3 图谱演进循环——扫描未消费 fact → 假设风暴（条件触发）（五路扩张：实体页/技法页/先例/图邻接/LLM 联想 → candidate 打分晋升——确定性因子命令计算+LLM 同分排序；dedup_key 机械拒重；rejected/deferred 留痕可翻案）→ 调度引擎 → 验证落账 → attack/cross_ref 链构建 → 收敛判定（四条件）或 budget-exhausted（预算三元组耗尽的合法终态）。专属视图：evolution-loop.html

⚙️ 2.3 Harness Engineering（脚手架工程）

哲学立场：复杂性放在「基础设施」里，而且尽量用现成的——不重写 agent 运行时，站在成熟宿主上做增量。工具调用、权限控制、沙箱、并发调度交给 harness。

它解决什么：agent 基础设施（工具协议、上下文管理、多代理、权限门）是重工程且快速演化——自建=永远在追平；方法论产品的价值在领域知识不在基础设施，重造轮子是资源错配。

架构原理
· 薄控制面：自己的指令面越小越好，宿主能力面用得越满越好——「五不原则」（不要求宿主改/不规定宿主内部/不干涉宿主调度/不假设宿主能力/不锁死宿主）
· 契约而非集成：与宿主耦合点收敛为契约（SKILL 目录格式+账本文件格式）；与引擎耦合点收敛为契约（manifest+统一提交格式+执行语义）——换宿主/换引擎都不动核心
· 渐进加载：常驻上下文最小化，按需加载 phases/——上下文是宿主最稀缺资源
业界谱系：Claude Code/walcode/CodeBuddy 成为通用 harness→MCP 工具协议标准化→dsh-pentester Docker 工具箱（重 harness 路线）→烛龙 HarnessExecutor→PentestCode fork 宿主（反面教材）
代价与边界：受宿主能力上限约束（并发模型/上下文窗口/权限粒度因宿主而异）；宿主差异需适配层吸收（探隐：指挥官协议+安装自检）；宿主停更/变协议是外部风险——契约面要小。
探隐选型：纯 SKILL 形态——不 fork 宿主、不做运行时、零代码依赖。子代理并发、命令执行、权限控制全复用宿主；引擎侧同理（vuln_agent 契约接入不重写）。烛龙成熟后 L2 适配器换成烛龙 runner，账本格式不变（schema_version 协商+一致性夹具验证）。专属视图：engine-contract.html + system-architecture.html（L5）

🧠 2.4 Context Engineering（上下文工程）

哲学立场：复杂性放在「上下文生命周期管理」里——上下文是 agent 最稀缺资源，它不是「装进来的」，是「被设计出来的」：什么常驻、什么按需、何时压缩、何时重启。

它解决什么：长循环 agent 的必然死法——上下文溢出或注意力衰减。溢出的实际表现不是干净恢复，而是纪律违反率上升、账本写错，恰好发生在会话尾部最需要严谨的阶段。

架构原理
· 常驻集 vs 按需集：安全规则/循环骨架/命令索引常驻（不得被渐进加载挤掉）；phases/知识页/契约按需
· 受管重启：每 N 轮或超阈值主动换会话，从盘上状态恢复——把「断电恢复」升级为常规操作（与状态外置联动：因为状态在盘上，所以重启无损）
· 摘要纪律：子代理返回结构化定长摘要（超限内容进盘）；查询命令输出摘要化（计数+top-N，禁止全量回灌）
· 注入遏制：敌意内容困在提交文件里，不进总控指令流——子代理隔离是安全边界，不只是成本优化
业界谱系：Anthropic compaction/structured note-taking 学科化→MemGPT/Letta 分页式工作记忆→Claude Code /compact 与 subagent 隔离
代价与边界：摘要是有损压缩（原始响应的「气味」丢失——允许按相关性回读 artifact 片段补偿）；checkpoint 写入有成本；重启有恢复延迟。
探隐选型：P3 每轮 checkpoint（state.md）+ 受管重启 + 子代理结构化返回 schema + 查询摘要化 + 常驻集清单——原设计最弱处（审计确认），立为显式支柱。落位视图：evolution-loop.html（⓪步） + engine-contract.html（提交文件协议）

2.5 四者关系：正交互补，咬合成完整工程

GraphLoopHarnessContext
复杂性放在状态过程基础设施上下文生命周期
回答的问题知道什么、怎么知道的接下来做什么、何时停在哪跑、用什么跑记住什么、忘掉什么
失效模式（单独用）死档案：记录完就完失忆循环：每轮丢状态空转轮子：有能力没方法溢出/衰减：越跑越糊涂
探隐落位L3 八表十边P3 演进循环+假设风暴L5 宿主+L2 契约总线state.md+受管重启+摘要纪律

咬合逻辑

Graph 给 Loop 提供状态载体与收敛判据——循环每轮读写图谱，收敛=图查询。

Loop 给 Graph 提供演进动力——图谱不会自己长，循环驱动它长到收敛。

Harness 给两者 提供运行环境——图谱是文件所以任何宿主可读写，循环是 LLM 指令所以任何宿主可执行。

Context 给三者 提供可持续性——状态在盘所以重启无损，摘要纪律所以循环不溢出，常驻集所以纪律不衰减。

四者中抽掉任何一个，其余三个都退化——这就是探隐架构选型四者全取、各取其长、显式落位的原因。
