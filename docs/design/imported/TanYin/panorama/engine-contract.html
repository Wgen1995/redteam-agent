🔒 引擎契约总线 · Harness 范式核心 · L2 层 · 文件契约总线

全类型渗透需要多种能力，全部自研不现实也没必要。探隐只定义契约——引擎异构（skill/cli/projector 三类），数据形状+执行语义双轴定义，提交文件协议统一，总控单写者落账。含 session-viz 实时可视化生成器。

契约双轴（engines/CONTRACT.md · 数据形状 + 执行语义）

要素内容原理
manifest 清单kind（skill/cli/projector） · 适用场景 · 参数 · 产物路径 · 超时/重试策略/幂等键（intent_id） · 纪律能力声明（CLI 引擎：max_op_level+视角上限）自描述——总控读 manifest 即知怎么调、能调什么；纪律能力声明让 CLI 黑盒不成为纪律旁路
输入session 目录 + 目标描述 + 已有 facts 摘要facts 摘要是跨引擎知识流动的入口（引擎不重复发现已知）
输出（提交文件协议 ）统一提交文件 → session/<goal-id>/submissions/<intent-id>/（schema 定死：findings[title/confidence/impact/reproducible_steps/evidence_refs/location] + facts[] + assets[] + edges[]），由总控验收后经账本命令统一落账——引擎不直接写账本单写者模式：并发锁/ID 撞号/校验集中化一次解决；提交文件是断点续传的额外恢复点；总控「验收格式」职责成立

执行语义（第二轴）：skill 型——LLM 子代理执行，失败=格式漂移/上下文耗尽，超时=回合预算；cli 型——OS 进程执行，失败=非零退出/超时/部分产物，必须声明纪律能力上限，总控据此路由（超限 intent 拒绝派发；黑盒工具默认最高风险级，仅 L0/L1 视角 intent 可派），适配器须输出操作日志供审计回放；projector 型——只读账本、产物不回写。

设计思想：文件契约总线——不引入进程间通信/消息队列/数据库，契约就是「目录+文件格式+执行语义」。零依赖、零部署、任何宿主可用。学烛龙「参数契约+产物映射器」语义，但落到纯文件形态。修正：引擎「零改动」过强——准确表述是契约内零改动（满足契约即插即用；契约演进时引擎跟版本）。

引擎矩阵（首批 + 预留）

web-blackbox 新写SKILL 型。CNPEN 方法论产品化：侦察 → 攻击面测绘 → 矩阵测试 → 差分举证（判定规则写入契约：同请求基线±单变量+errorCode 语义分析+内容类型验证）。装进子代理按角色 recon/web 执行。引擎级详细设计已定稿（2026-09-18-web-blackbox-engine.md：目录结构 SKILL.md+phases 四段+patterns 提交模板；intent.kind→段映射；上下文预算——工具输出零进上下文；失败语义五类——格式漂移/上下文耗尽/超时/环境受阻/工具失败；CNPEN 82 漏洞素材→引擎/技法页/先例库映射）。
vuln-agent 接入CLI 型适配器。已有成熟白盒工具：启动命令按 OS 参数化（Windows: python / POSIX: python3） → .vuln_agent_output/ → 适配器归一化成提交文件；max_op_level: read + 操作日志输出。
session-viz 新写projector 型可视化生成器（归类修正：只读账本、产物不回写）。读 session 账本（八表+矩阵+timeline）→ Cytoscape.js 交互式 HTML（离线自包含）。统计栏/Pipeline 时间轴/图谱区/攻击链面板/未消费 fact 清单/预算消耗进度条——实时感知渗透测试现状。账本即数据源，零额外状态。
gencpt 契约预留容器/K8s 渗透 SKILL。契约已兼容（SKILL 型），暂不接入。
未来引擎 扩展位AD 域 / 移动 / 云配置审计…新增引擎=写 manifest（含执行语义+纪律声明）+适配说明，契约内总控零改动。
原理逻辑：为什么 web-blackbox 新写而 vuln-agent 复用？——CNPEN 方法论（82 漏洞实战验证）没有现成产品化实现，是探隐的差异化核心，必须新写；vuln_agent 已是成熟工具，适配器接入成本远低于重写。方法论层自研、工程模式层复用、引擎层契约接入。

实时可视化（session-viz · projector · 测试现状直读）

机制：账本即数据源——session 目录的八表 TSV + E-index + matrix + timeline 就是可视化输入，不需要额外记录。`用探隐可视化` 命令随时重新生成；HTML 离线自包含（Cytoscape 内嵌），单文件可发送任何人。

呈现：统计栏（资产/fact/finding 按 confidence×impact 分色/攻击链/矩阵覆盖率/收敛进度/预算三元组消耗进度条/风暴指标——candidate 池大小、五路产出分布、deferred 池）· Pipeline 时间轴（P0-P6 含 P5.5 签发/P6.0 清理门状态，当前阶段高亮）· 图谱区（节点按类型着色、finding 按 confidence×impact 发光、attack 链金色动画、cross_ref 虚线、supersedes 点线；candidate intent 半透明虚线节点——风暴中的假设 vs 已验证实线节点；过滤/搜索/布局切换）· 右侧面板（节点详情/攻击链步骤展开/未消费 fact 清单/假设风暴面板——五路产出列表，每 candidate 显示 origin 徽章+score+via 引用，rejected/deferred 折叠可查/清理清单视图——P6.0 核销状态）。

设计思想：账本是单一事实源，可视化只是它的一个投影——零额外状态、零同步成本、重新生成即最新（断点续传/受管重启后同样反映恢复点状态）。把「图谱收敛=测试完成」从账本查询变成肉眼可见。来源：GenCPT graph-viz（Cytoscape 模板+离线自包含）。

跨引擎知识流动（总控独有增值）

Web 黑盒发现端点清单 → 注入白盒审计重点（cross_ref 边：这个端点的处理代码在哪，重点看）
白盒发现硬编码密钥 → 注入 Web 测试素材（cross_ref 边：拿这个密钥去试认证绕过/签名伪造）
finding A（任意文件读）+ finding B（配置泄露路径）→ attack 边：组合成攻击链
设计思想：单引擎产品看不见跨域组合——Web 扫描器不知道源码里有个密钥，白盒工具不知道线上有个端点。总控让两类信息在同一账本汇合，组合推理（P3 第⑤步链构建）产生 1+1>2 的发现。这是「编排」相对「堆工具」的本质区别。

工具调用分层（Kali 工具箱怎么接——不逐工具写引擎）

层什么工具接入方式纪律
引擎级大工具，结构化产物，独立能力域（vuln-agent 这类完整引擎）kind: cli 契约：manifest 声明纪律能力上限（max_op_level+视角），适配器归一化产物为统一提交格式黑盒工具默认最高风险级，仅 L0/L1 视角 intent 可派发；操作日志供审计回放
命令级小工具：nmap/nuclei/subfinder/httpx/curl…SKILL 型引擎与子代理执行任务时经执行通道（宿主 shell）直接调用——工具是命令，不是引擎三重门横切：deny-list 机械拦截（执行前置）→ scope-check（intent 派发前置）→ rate_limit（goal 级限速）；对外请求记 timeline request: 事件
设计思想：工具知识归知识库，不写死在代码里——「哪个工具+什么参数+适用什么技法」存 concepts/ 技法页与 precedents/ 命令模式，风暴第②路检索技法页时即获得工具用法。新工具加入 = ingest 一篇用法文档成技法页（走 staging 审批门），不是改代码。分界判据：产物需要独立归一化+独立纪律能力声明→引擎级；只是命令行调用→命令级。方法论级差异（Web 黑盒/源码审计/容器/AD 域）才需要新引擎；攻击手法差异（SQL 注入 vs 越权）只是知识页差异。

烛龙对齐（预留接入，不依赖）

机制：探隐契约 = 烛龙「参数契约+产物映射器」的语义版；TSV 账本 = 烛龙 NDM 的文件版（schema_version 列作为映射协商基础）。接入时 L2 适配器 SKILL 换成烛龙 runner 调用，L3 账本格式不变。探隐独立发布，不依赖烛龙存在。

一致性夹具：烛龙 runner 跑 stub 引擎对黄金 session 产出一致账本——列入烛龙接入批次验收，把「零成本接入」从声明变为可回归的契约测试。

原理逻辑：分层解耦的兑现——L2 是可替换层。烛龙成熟后，探隐 session 目录可直接导入烛龙平台，获得 GUI/多用户/调度能力；不接入时探隐照常独立工作。诚实修正：两边执行语义此前都未定义，对齐无从谈起——现在探隐侧已定义（契约双轴），夹具让对齐可验证。
与工程范式的关系：本图是 Harness 范式的落位——不重造引擎、不重造运行时，站在成熟工具（vuln_agent）与成熟宿主（walcode/CodeBuddy）上，探隐只做它们都不做的那一层：契约与编排。提交文件协议同时是 Context 范式的落位（结构化摘要进上下文，超限进盘）。
