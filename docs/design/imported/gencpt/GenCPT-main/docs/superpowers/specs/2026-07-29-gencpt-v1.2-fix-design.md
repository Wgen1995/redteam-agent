# GenCPT V1.2 修复与优化设计规格

> 日期：2026-07-29
> 状态：已批准
> 范围：39 个问题 + 7 个横向补充 + ARE 对抗机制 + 可视化增强 + 初始环节质量门控 + 字段质量保障 + SKILL 拆分 + Token 预算删除 + 跨平台兼容性
> 方法：分层修复（编排层→校验层→图谱层→Phase 层）

---

## 一、背景与目标

### 1.1 问题来源

对 GenCPT V1.1 在 k3s_server 环境的一次完整 full 模式运行做了全量分析，发现 39 个问题：

| 类别 | 数量 | 典型问题 |
|------|------|---------|
| 架构层（A1-A7） | 7 | 编排层门控缺失、KG 无自洽性校验、确定性操作与语义判定未分离 |
| 执行层（B1-B10） | 10 | Recon 采集 11/26 Pod、原始证据未落盘、progress.json 不执行 |
| 已知未修复（C1-C3） | 3 | 改名悬空、未验证无标记、缺对象级关联 |
| 新发现（N1-N8） | 8 | 9 个子技能无 progress.json、evidence 命名不一致、降级规则不对齐 |
| 字段质量（D1-D4） | 4 | attack 边无 attrs、finding 无 evidence、Pod 缺 7 个安全上下文字段 |
| 横向扩展（H1-H7） | 7 | 悬空边全 Phase 蔓延、finding evidence 全平台缺失、raw 命名全 Phase 不统一 |

### 1.2 设计哲学确认

GenCPT 的四根设计支柱经分析确认正确：

1. **KG 是第一性原理** — Phase 产什么数据由 KG Schema 决定，报告是副产品
2. **检索优先 LLM 补充** — 静态库高置信度优先，LLM 推理标 `[?]` 需验证才升级
3. **推理 = KG 上的图操作** — LLM 对 KG 节点推理，不对原始 SSH 输出猜
4. **可追溯性是反幻觉深层机制** — KG 让 LLM 没法隐瞒说了谎

本次修复新增第五支柱：

5. **确定性操作与语义判定分离** — 采集/校验/图遍历用 bash 命令（确定），判定/推演/报告用 LLM（灵活）。LLM 可调用 bash 命令做确定性对比，但不写代码程序工具。

### 1.3 修复约束

| 约束 | 说明 |
|------|------|
| 纯 LLM 自然语言识别 | 不写 Python 脚本工具，校验指令写进 SKILL.md 让 LLM 执行，LLM 可调用 bash 命令做确定性对比 |
| 跨平台兼容 | 必须兼容 opencode + Claude Code |
| 质量第一 | 可连接 k3s_server 实际调试验证效果 |
| 分层修复 | 编排层→校验层→图谱层→Phase 层，逐组验证 |

### 2.1 入口 SKILL §4 断点续传重写

**问题**：§4 断点续传 step 4/5 缺主语，17 个子技能中只有 3 个有完整 progress.json 更新。

**方案**：

入口 SKILL §4 "断点续传"小节重写为：

```
### 断点续传（入口 LLM 统一接管）

每个 Phase 调用前（入口 LLM 执行）：
1. 读取 progress.json，检查该 Phase 状态
2. 若状态为 complete，跳过
3. 若状态为 in_progress 或 failed，询问用户是否重新执行
4. 入口 LLM 将该 Phase 状态更新为 in_progress（写 progress.json）
5. 入口 LLM 调度子代理（Task(general, prompt=...)）

子代理返回后（入口 LLM 执行）：
5b. 入口 LLM 验证该 Phase 的 MUST 输出文件存在且非空
5c. 验证通过 → 入口 LLM 将状态更新为 complete
5d. 验证失败 → 入口 LLM 将状态更新为 failed，询问用户是否重试
```

**关键变更**：
- step 4/5 明确主语为"入口 LLM"
- 新增 step 5b：MUST 输出验证才写 complete
- 子代理 SKILL.md 中的 progress.json 更新指令全部删除

### 2.2 入口 SKILL §4 调度原则增加并发重试

**问题**：Phase 2a 并发时被 cancel、空返回，无重试。

**方案**：调度原则增加：

```
调度原则 11：并发调度重试
- 并发调度的子代理若返回空结果或被 cancel，自动重试 1 次
- 重试仍失败则退化为单独顺序调度
- 仍失败则标记该 Phase 为 failed 并询问用户
- 适用于 Phase 级并发（如 2a+2c、8a+8b）和 WU 级并发
```
