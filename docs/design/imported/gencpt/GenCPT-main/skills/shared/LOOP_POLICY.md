# 循环使用策略（LOOP_POLICY）

> 适用范围：所有 Phase 子流程中是否启用循环。
> 约束力：**强制**。

---

## 1. 核心原则

循环适合"对错清晰可验证"的活；安全检测的攻击验证和可信度判定不该让循环碰，故主体不循环。

---

## 2. 三个适用循环的子流程（局部，≤3 轮）

| 子流程 | 循环触发条件 | 验收方 | 停止条件 |
|--------|-------------|--------|---------|
| Phase 4a 未匹配信号复查 | Phase 4a 全部模式验证完后 | 独立子代理复查 [?] 信号是否遗漏模式 | 新增命中 ≤0 或 ≤3 轮 |
| Phase 6 链验证争议仲裁 | Phase 6 第一轮验证后争议 | 第三方仲裁子代理 | 共识达成或 ≤3 轮 |
| Phase 8c QA 语义抽检复检 | QA 抽检发现不一致 | 子代理重新 ssh_execute 验证 | 一致或 ≤3 轮 |

### 2.1 每轮 self-contained 原则

下轮子代理只读上轮结论 + 源数据，**不读上轮推理过程**。这避免"自我合理化"持续加固幻觉。

### 2.2 循环充分性判断

每轮循环由 LLM 自行判断是否充分，不设硬上限。判断不充分或仍有未闭环项时继续下一轮；≤3 轮上限仍适用（见 §2 表格）。

---

## 3. 禁止循环的子流程

| 子流程 | 禁止理由 |
|--------|---------|
| Phase 2 合规检测 | 规则数固定（226条），无需循环 |
| Phase 4a 模式匹配 | 条件触发表是静态的，命中即命中 |
| Phase 5 链构建 | 图谱搜索是确定性的 |
| Phase 9 模式进化 | 4项门槛是客观判断，无需反复评估 |
| L2 攻击验证 | 差分证明是事实验证，不存在"再试一次" |

---

## 4. WU 失败重试策略（非循环，是重试）

WU 失败时：
1. 最多重试 2 次
2. 仍失败则降级为 `[!] 环境干扰`，记录到 issues 字段
3. 不许无限重试（防止死循环）
4. 重试间隔 5 秒（遵守 SSH 限速规则）
