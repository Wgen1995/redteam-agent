# poc-generator 破坏性 POC 标注与回滚步骤规范

> 本文件为 `skills/poc-generator/SKILL.md` 的破坏性 POC 安全规则参考。核心工作流见 SKILL.md。

---

## 破坏性 POC 标注规则

### 何时标注 destructive: true

满足以下任一条件的 POC 必须标注 `destructive: true`：
- 攻击命令可能导致服务中断（如 fork bomb、资源耗尽）
- 攻击命令可能修改宿主机状态（如持久化后门、修改系统配置）
- 攻击命令可能导致数据丢失或不可逆变更

### 破坏性 POC 脚本要求

1. **脚本头部标注** `destructive: true`
2. **不执行实际破坏性命令** — 只展示理论路径
3. **提供条件验证替代证据** — 用 [L0]/[L1] 非破坏性检查替代
4. **附回滚步骤** — 说明理论上需要的回滚操作
5. **标注 ⚠️** — 在 POC 标题和输出中标注破坏性警告

### 破坏性 POC 格式

```bash
#!/bin/bash
# POC: <攻击名称>
# destructive: true
# 可信度: C2 条件实证 ⚠️
# 验证层级: L3
# ⚠️ 本POC包含破坏性操作，仅提供条件验证替代证据
```

## 回滚步骤规范

### 通用回滚步骤

1. 清理 `/tmp/poc-*` 临时目录
2. 清理上传的临时工具 (`rm -rf /tmp/cpt-tools/`)
3. 删除 POC 创建的临时容器/Pod

### 非破坏性 POC 的回滚

- 每个 POC 脚本**必须包含清理步骤**章节
- 清理命令必须可实际执行
- 清理后必须有确认清理的检查命令

### 破坏性 POC 的回滚

- 脚本中标注"本POC未执行任何破坏性操作，无需回滚"
- 附理论上需要的回滚步骤（如果将来需要实际验证）
- 回滚步骤格式：
  ```
  echo "### 回滚步骤 ###"
  echo "本POC未执行任何破坏性操作，无需回滚"
  echo "如果将来需要实际验证，回滚步骤如下："
  echo "  1. <回滚步骤1>"
  echo "  2. <回滚步骤2>"
  ```

## 审批要求

| 验证层级 | 审批要求 | 说明 |
|---------|---------|------|
| L1 | 无需审批 | 只读探测 |
| L2 | 标准/自动 | 根据会话配置 |
| L3 | 快速/自动 | 条件验证，非破坏性 |
| L4 | 手动确认 | 逃逸验证 |
| L5 | 不可安全复现，理论验证 | 不可安全复现 |

**超出审批范围立即停** — L5 操作不生成实际执行命令，只提供理论推导。

## 风险警告

⚠️ **重要风险提示**：

1. **执行环境风险**：所有 POC 在生产环境执行前必须在测试环境验证
2. **数据泄露风险**：部分 POC 可能读取敏感数据（Secret、证书等），执行后立即清理
3. **服务中断风险**：标注 `destructive: true` 的 POC 可能导致服务中断
4. **不可逆操作风险**：部分攻击步骤可能创建持久性后门，务必执行清理步骤
