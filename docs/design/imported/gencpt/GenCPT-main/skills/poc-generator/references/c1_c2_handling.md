## C1/C2 POC 区别处理规则

### C1 实证复现

- **条件**：5 项门槛全满足 + L2 差分证明
- **POC 类型**：完整可执行 POC
- **脚本要求**：
  - 包含实际攻击命令（[L2] 标注）
  - 包含攻击前/后差分证明（[L0] 基线 + [L0] 观测对比）
  - 包含实际清理命令
  - 标注 `C1 实证复现 ✅✅`

### C2 条件实证

- **条件**：前置条件满足 + 理论链路完整
- **POC 类型**：条件验证 POC（标注 ⚠️）
- **子类型**：
  - **C2 可安全复现**：前置满足但需特定条件，POC 可执行但附条件说明
  - **C2 不可安全复现**：实际执行影响生产环境，只提供理论推导 + 替代证据
- **脚本要求**：
  - 标注 `⚠️ 可信度: C2 条件实证 ✅`
  - 不可安全复现时标注 `验证层级: L3` + `不可复现原因: xxx`
  - 理论攻击路径步骤标注 `[⚠️ L3-条件验证]`
  - 必须包含替代证据章节（[L0]/[L1] 非破坏性检查）

### C3 风险线索

- **不生成 POC** — 仅在报告中记录为高风险线索

## 差分证明的 L0 观测要求

生成 POC 脚本时，根据攻击类型强制要求差分证明包含 L0 观测：

| 攻击类型 | L0 观测要求 | 说明 |
|---------|------------|------|
| AS-1 逃逸 | **必须**包含 `[L0]` 攻击前基线快照和 `[L0]` 攻击后观测对比 | 逃逸影响宿主机状态 |
| AS-5 DoS | **必须**包含 `[L0]` 攻击前基线快照和 `[L0]` 攻击后观测对比 | DoS 影响宿主机资源 |
| AS-7 持久化 | **必须**包含 `[L0]` 攻击前基线快照和 `[L0]` 攻击后观测对比 | 持久化修改宿主机状态 |
| 其他攻击类型 | 至少包含 `[L1]` 基线和观测 | 容器内观测即可 |
| hostpath-mount | `[L0]` 检查 + `[L1]` 读取，无 L2 执行 | 特殊例外 |

**不满足 L0 观测要求的 POC**：在 poc_readme.md 中标注"⚠️ 差分证明不完整，可信度降级为 C2"
