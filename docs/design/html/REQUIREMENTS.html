探隐 TanYin — 需求总纲（用户诉求最高权威）

探隐设计文档站 · REQUIREMENTS

1. 一句话愿景

构建「探隐 TanYin · 全类型 AI 渗透测试总控」：一个纯 SKILL 形态、复制即装的渗透测试套件——AI 负责挖（引擎执行）、纪律负责管（契约约束）、图谱负责推（演进驱动）、知识负责长（先例复利）。装进 walcode/CodeBuddy/Claude Code 等任意编码 agent 即可使用。

2. 产品定位与形态

  • 生态位：全类型渗透总控（Web 黑盒 + 白盒源码审计 + 未来容器/AD 等），不是单引擎
  • 技术形态：纯 SKILL 编排（零代码依赖、零运行时、复制即装），LLM 语义驱动 + 账本确定性
  • 与烛龙关系：独立优先，预留接入（引擎契约对齐烛龙插件体系，后期零成本接入）
  • 首批引擎：web-blackbox（新写，CNPEN 方法论产品化）+ vuln_agent（CLI 适配器接入）；GenCPT 契约预留不接入
  • 目标用户：安全团队渗透测试工程师（在编码 agent 中使用）

3. 核心诉求（用户原话提炼）

  1. 通用可复用：直接安装到 walcode、CodeBuddy 等使用
  2. 全类型渗透：不止 Web，编排多引擎
  3. 不断增强：每次测试的知识跨会话沉淀复利（wiki 摄入 + 先例回写 + 模式进化）
  4. 图谱驱动：像真人头脑风暴——侦测信息→分析→攻击面演进→推导验证→图谱收敛即测试完成
  5. 安全纪律：授权门 + 分级审批 + 命令安全上下文（攻击者视角分级）
  6. 覆盖可度量：五态标记、矩阵闭合、终态门禁——从"看运气"变"可度量"
  7. 工程化管理：蓝图→设计→进度→账本（参考烛龙开发模式）

5. 交付物形态

可安装的 SKILL 套件（git 管理）+ 设计文档链（本总纲→设计定稿→实施计划）+ panorama 活文档 + 演进记录 + 架构原理图（汇报用）。

6. 工作方法论（铁律）

  1. 设计无分期：所有层一次性完整设计到无二义；唯一分步=实现批次解耦（批次间接口已定死）
  2. 探知项机制：实现期才能知道的细节显式列清单，发现后回写
  3. superpowers 流程：一次一主题、先问用户预期、用户点头才落档
  4. 全景活文档：panorama/ 随演进强制同步
  5. 会话纪律：一切状态落文件，新会话从文件无损恢复

7. 验收标准

  • 黄金夹具校验通过（账本命令输出逐字节一致）
  • 授权靶场全流程跑通并产出报告
  • CNPEN 82 漏洞 ingest 后知识库抽查正确
  • 在 walcode 与 CodeBuddy 双宿主实际安装可用
