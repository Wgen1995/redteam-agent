# multica 产品级「AI 辅助安全能力」分析（镜头修正版）

> 用户修正令（2026-10-15）: 安全红队=用户在 multica 上的 TanYin 实践，非产品能力。本档只评 multica 这个**产品本身**对 AI 辅助安全作业的承载力。素材: 1-multica.md（源码级）+walk-multica.md+usage-guide-multica.md。

## 一、产品原生提供的安全相关能力（承载面，全部有文件级出处）

| 能力族 | 产品原生机制 | 对 AI 安全作业的意义 |
|---|---|---|
| 人机混编组织 | squad（leader 路由制）/成员五态/可见性三档/invoke 门 | 安全小队的组织容器: 谁在打、谁审、谁可见 |
| 任务流水线 | issue 状态机（服务端副作用全表）/stage 屏障/自定义状态 | 攻击分阶段推进的工程化（侦察→利用→报告）|
| 人在环 | 评论触发/触发预览（先算谁被唤醒）/waiting-on-human 失败态/inbox/IM 五渠道 | 审批与升级的**通道**（非判定）|
| 运行审计 | execution_log 全回放/transcript/**30 条失败 taxonomy**/**on-behalf-of 归因链（9 源）**/task token/.task_owner | 运维级取证: 谁触发的、为何失败、怎么死的 |
| 执行卫生 | daemon 认领+**10 项能力协商**/workdir 每任务隔离/AGENTS.md 契约注入/repo worktree 纪律 | 攻击作业的进程隔离与可复现环境 |
| 治理 | RBAC 三级/usage 每运行计量（自定义定价）/Stop/队列+Steer | 成本与权限的闸（不问内容只问配额）|
| 自动化 | autopilot（schedule/webhook，投递幂等+重放）/wakeups（自触发防护）| 周期性巡检/回归扫描的触发器 |
| 工具面 | MCP 双层（工作区+私有，写审计/读脱敏）/插件第二 origin | 安全工具可挂载，但**零原生安全工具** |

## 二、产品没有的（安全实质面）

1. **无范围执法**: 不存在 scope guard——agent 扫描范围外目标，产品无感。
2. **无真值底座**: Postgres 可变库，无哈希链/防篡改; execution_log 是运维日志不是证据链。
3. **无验证纪律**: 无重放复现/无 GT 对照/无统计度量——发现真假靠 agent 自觉。
4. **无覆盖模型**: issue ≠ 攻击面; 没有资产图/锚点/覆盖度计算。
5. **无凭据保险库**: env 有审计、MCP 有脱敏，但无 vault 占位符机制（账本可见而真值永不上账）。
6. **零安全工具**: 不带扫描器/代理/DENYLIST——它是 PM 平台，不是安全平台。

## 三、专业判决

**multica 对 AI 辅助安全的价值 = 「组织编排层」而非「安全能力层」（置信 0.88）。**
它供应的是**形态**（组织/通道/配额/归因），不供应**实质**（范围/真值/覆盖/验证）。安全实质必须来自其上运行的方法论（用户的 TanYin 实践恰好补了这层——这正是二者关系的实证: 平台出形，实践出魂）。
对探隐: 互补分工维持（multica=多项目组织层，探隐=单战审计+自主战斗层，薄桥互通）; multica 不因此升格为二开对象。
**翻案条件**: multica 经其插件表面原生出货 guard/egress/验证类能力（届时补齐实质，与探隐正面竞争）→ 届时重评。

## 四、追加偷单（组织层平台件，v1.0b 用）
① 能力协商协议（daemon caps 10 项）② 触发预览（派单前算谁被唤醒）③ on-behalf-of 归因链（autopilot 归因到规则发布者）④ 30 条失败 taxonomy（失败面板）⑤ 每运行 usage 计量+自定义定价口径。
