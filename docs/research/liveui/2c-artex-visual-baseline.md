## 0. 方法与诚实声明（必读）

**本子代理的运行时模型（glm-5.3）没有图像输入能力，read_image 全部被拒**（报错原文: "model does not declare image input"）。因此本报告**没有任何一条来自"看图"**。为不装瞎、不编造，全部视觉事实改由三类机器证据构成，每条观察后标注来源，任何人可复跑核验：

- **[DOM]** Playwright + 系统 Chrome headless，视口 1440×900，`waitUntil: 'domcontentloaded'`，对 ARTEX 本地文件与探隐 8900 七页活体做的 getBoundingClientRect / getComputedStyle / innerText 普查（2026-10-16 09:19–09:35）。坐标均为四舍五入整数。
- **[像素]** Python PIL 对 PNG 的统计: 背景主色占比、墨水密度（与背景差>22 的像素占比）、12×8 密度网格、24 列带剖面。
- **[档]** 既有档案: `2b-artex-export-ui.md`（主会话对同一导出页的分析）、`walk-tanyin.md`（v0.9c 五页 before 基线）。

**给后续读者**: ARTEX 截图在 `shots/artex-ref/01-top.png`。该页恰好 900px 高、无整页滚动，所以"首屏=整页"，只存在一张有效截图（曾多截的 05-fullpage.png 与其同字节数，已删除）。**强烈建议把这张图交给真正有视觉能力的模型复核第 1 节**——DOM 证据已保证布局事实，但"好看不好看"的审美判断超出本报告能力，本报告不妄下。

## 2. ARTEX 有而我们没有的可操作件清单（用户核心痛: 我们几乎零按钮）

先摆数字 [DOM]: **ARTEX 单屏 = 18 button + 23 link + 10 标签 + 1 模型芯片 + 1 折叠钮 + 3 画布钮。探隐 v0.9d 每页 = 1–2 button（"深色"主题切换 / session 页另有"重载"）+ 1–2 select（"战局切换"21 项, session 页两个）+ 9–14 个 nav link, 全站 svg=0。**

| # | ARTEX 可操作件 | 位置 | 探隐现状 |
|---|---|---|---|
| 1 | 侧栏折叠钮（Toggle Sidebar） | 顶栏左 | ❌ 无 |
| 2 | 模型/引擎选择芯片（GLM, "查看或切换任务 LLM 配置"） | 顶栏右 | ❌ 无（可改造为"数据源口径切换"） |
| 3 | 归档任务图标钮（aria="归档任务"） | 顶栏右 | ❌ 无 |
| 4 | 深色实心主按钮（"恢复"） | 顶栏右 | ❌ 无任何主操作钮 |
| 5 | 任务子标签 ×10（同页切视图） | 顶栏下 | ❌ 无（探隐换视图=侧栏整页跳） |

**公道话（同样 [DOM]）**: ARTEX 导出页自己也是 0 input / 0 select / 0 textarea——它的"可操作感"全部来自**按钮+标签+图标+折叠**这一层, 不来自表单; 探隐连这一层都缺。反过来, 探隐已有 4 件 ARTEX 导出页没有的: 战局切换下拉（21 项）、深浅主题切换、首页 KPI 数字是链接（14 个 a 中 5 个是 KPI 跳转）、证据卡/图节点的 JS 点击展开。**所以补齐方向明确: 不是加表单, 是补"钮/签/标"层。**

## 4. 给「工艺舰」的追加建议——与「方向盘批」明确分流

**工艺舰（字体/间距/颜色/纯 CSS 能解决的, 立刻做）**:
1. 次要文字统一用"前景色 60% 透明度"手法（参照未激活标签 oklab alpha .6 [DOM]）, 不另起颜色——12 级灰阶按 2b 档执行。
2. 活动流/表格数字: `tabular-nums`; 时间戳短格式"月-日 时:分"+hover 全量（纯渲染层改写）。
3. 预算卡 >80% 琥珀、>95% 红 + 一行"消耗速率"文案（首页 H2 已承诺变红, 先把样式兑现）。

5. **手绘 12–16 个 16px 线性 SVG 图标**（侧栏 9 项+顶栏 3 件）——图标是"可操作感"的底层, 且属于工艺批能交付的; 参照 325 个图标 vs 我们 0。
6. 侧栏组间"小标题+48px 空隙"的分组节奏照抄（坐标见第 1 节区A）。

**方向盘批（功能件缺失, 字体颜色永远解决不了的, 归下一批）**:
