# P3 · 演进循环（方法论指令）

入口：仅经 P2 门进入（gate-exit:P2 在场）。每轮六步，任何写操作只走账本命令。

## duty（每轮命令序列）
⓪ checkpoint --session <本会话> --phase P3 --round <r> --timestamp <T>；budget-check（树形余量，任一维穿=收敛判定走 budget-exhausted 分支）。
① 扫描三查询：unconsumed-facts / pending-intents / matrix-gaps（各一次，计数+top-N）。
② 假设风暴五路（条件触发；你提议、命令判定）：
   - entity 路：新资产/新 fact 派生 → add-intent --origin=entity
   - concept 路：技法页命中 → add-intent --origin=concept --via <技法页引用>
   - precedent 路：先例三元组匹配（批次 5 知识库；本批可空）→ --origin=precedent
   - adjacency 路：邻接攻击面联想 → --origin=adjacency
   - llm 路：自由联想，每轮 quota=5（弱模型档=0）→ --origin=llm
   dedup_key 由 add-intent 机械计算（重复键 REJECT=已有同类，不重提）；
   candidate→pending 晋升阈值=0.5+0.05*(round-1)（读侧 score 低于阈值=留 candidate，reason 留空）。
③ 并行派发（优先级调度 fb72cd5）：每轮从 pending intents 按 priority 降序取 Top-K（K=预算/并行度），高危路径先行；先 tanyin-budgetctl enforce --intent-id <id>（超份额拒派）；再 tanyin-phases cached --intent-id <id>（SKIP=不派）；派发走六要素委派单（子代理只产 submissions/<intent-id>/submission.json）；引擎 intent 按 MANIFEST 纪律能力路由（超 max_op_level/视角上限的 intent 拒派）。

### 派发优先级算分（fb72cd5；确定性公式，Top-K 选择=总控决策）

priority = severity_expect × asset_value × exploitability

- severity_expect（0-1）：intent 目标漏洞类的严重度期望——类型基线表=knowledge/methodology/k1-baseline.tsv（G-24 已落表，批5 T12：WSTG 12 全类+细类行，初值=WSTG v4.2 严重度倾向+CNPEN 复盘校准，人审冻结；查表次序=细类→wstg 类→缺省 0.5+告警）。
- asset_value（0-1）：目标资产业务价值——取 assets.meta `bv:<0-1>` 人标业务价值（人握方向盘；未标=0.5 中性，不加分）。
- exploitability（0-1）：可利用性——0.4×可达（graph-horizon 语义：scope-root 可达集含该资产，reachable_gap_cells 单源）+0.3×active creds 在手+0.3×先例命中（批次 5 知识库三元组匹配）。
- 承载：读侧=tanyin-knowledge score（CLI 只读算分：查表+三因子与乘积 stdout 单行 JSON，sources 附查表行/可达计数/凭据计数/命中页，可审计复算）；intents.priority 经 add-intent --priority 回填落账（契约 01 勘误登记，物理列批5 T3 已落），算分与落账分离；Top-K 选择=总控决策不变（契约 09 §4 边界 2）；禁黑箱。
④ 验收落账：按提交 schema 验收，逐条 add-fact/add-finding/add-asset/add-edge/add-cred 落账（单写者；REJECT=打回子代理重写一次）。高危（impact∈{高,high,critical}）finding 落账当刻即提同型横向 intent（kind=matrix-test/deep-dive，title/detail 内联来源 FD-id）；轮内不横向=落 add-fact --target=lateral:<FD-id> 披露 fact（trigger-audit ④机检，批5 T6）。
⑤ 链构建：add-edge --kind attack / cross_ref（proves/yields 边随 ④ 命令铸）。
⑥ 收敛判定：converge-check → converged 或 budget-exhausted 才可过门（tanyin-phases gate --phase P3）；running=继续下一轮。budget-exhausted 分支：未闭合格按 priority 降序披露「未覆盖的代价」（报告整改优先级与调度同公式——一套分值两头用）。

## 回边（不离开 P3 的三事件 + 触发后命令序列）
- asset-added（④ 验收发现新 in_scope 资产）：add-asset 已落 → add-intent --origin=recon-event --kind=recon（直达 pending 不打分）→ 子矩阵行（matrix-set --reason=submatrix: …铸新表面×词表全集，G-2）→ Nday 匹配（tanyin-knowledge nday-match --cpe=<assets.meta 指纹> --version=<v>；命中→add-intent --kind=nday-verify --via=<cve_id>，G-18 引擎映射=nuclei——组件指纹形态=cpe:<vendor>:<product>;v=<版本>，recon A8 采集位）→ 计入预算（budgetctl enforce 不豁免测绘）。out_of_scope 资产只记 fact 不 spawn。
- cred-obtained（获得登录态/攻击凭据）：add-cred --kind=session --parent-cred <父>（真值入 vault，secret_ref 占位符）→ authz-diff 候选：受保护端点×active creds role 笛卡尔积逐对 add-intent --kind=authz-diff --origin=entity --cred <CRED-id> --actions <计划动作>（直达 pending 不打分，裁决 R5；单端点对数上限 24=AUTHZ_DIFF_PAIR_CAP——cli/ledger/write_cmds.py 代码常量单源，机检=add-intent 写前拒收、--cap 覆盖通道=evals，批次5 T5，R6）。
- scope-amended（客户扩授权）：amend-scope --approval <AP-id>（未经审批=账本级 REJECT）→ tanyin-egress compile 重编译 ACL/DNS/OOB → 界外资产复判（scope-check --all-assets）→ 转正资产初始化子矩阵行 → tanyin-canary deploy+probe 复测（干跑模式只 deploy）。

## 受管重启触发（本门独有）
- 自动档：上下文用量≥0.75（restart_context_threshold）或距上次重启≥10 轮（restart_every_n_rounds）→ tanyin-phases restart --spawn auto（护栏：计入预算/速率上限/单活跃会话锁——递归 spawn 会被速率上限与 budget-exhausted 双重掐灭）。
- 兜底档：kill -9/断电后，恢复协议（verify-chain→state-rebuild→resume-kit）走完 → restart --spawn manual（须 state-rebuild PASS 才接管旧锁）。

## 收敛判定语义（终审补全 1）
空格清零（主矩阵+子矩阵）/预算树未穿/无 unconsumed fact/无 blocked intent——四条件全真=converged；预算穿=budget-exhausted（合法终态）。发散由事件链保证（新面不断进入），收敛由锚点+风暴阈值递增保证——收敛是动态平衡。
