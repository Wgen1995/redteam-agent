发现 1 · 总体分层：四层堆叠+15 支撑子系统

Go 单二进制 · 内嵌 Next.js · PostgreSQL——部署即一键，工程成熟度的来源

  • 前端 Next.js（go:embed 内嵌 :8787）：仪表盘/任务/资产/覆盖图/探索链路/流量/人在环路对话/审批/LLM 配置
  • server（Go net/http）：REST /api/* + JWT 鉴权 + SSE 活动流；Manager 托管任务/引擎/store 生命周期
  • engine（每任务）：plannerLoop×1（唯一意图源，防 worker 自增殖）+ worker goroutine×N
  • 支撑 15 件：traffic MITM :8788 / intercept+guard / llmpool / llmrec / notify 钉钉飞书邮件 / enrich / evidence / report / mcphttp / selfupdate（3 连败回滚）/ skills / sidequestion / norma SDK（vendored 210 文件）

发现 2 · 双图架构（核心创新Ⅰ）：过程 ⇋ 锚点 ⇋ 真值

探索图=过程链（每任务独立）⇋锚点桥表⇋资产图=真值库（全局共享）

  • 探索图血缘边四件套：spawns/yields/derived_from/proves——回答「这个方向派生自哪些事实、产出了什么」
  • 资产图实体链：company→root_domain→subdomain→ip/service→endpoint——父子关系与去重 key 全由程序计算（不信 LLM 画图）
  • 锚点桥表 exploration_anchors(node_id, asset_id)：方向→打过哪些资产/资产→被哪些意图测过 ⇒ 资产覆盖度+覆盖图
  • 我们的对照：10 边对 4+锚点——scope-rel/evidences/supersedes/attack/cross_ref 是执法语义超集（详见界面地图页图B）

发现 3 · 事件驱动引擎闭环（核心创新Ⅱ）

图变更→planner→frontier→worker→MITM 执行→写回→再唤醒——直到 prove_goal

  • 图变更 debounce：资产图/探索图任何写回都触发
  • planner 唤醒=全新无状态会话（graph_overview 预取+coverage/scope 读态势）；多数唤醒派 0 条意图
  • worker claimNext 领一条、做完即停；真实工具执行（Kali/Bash/HTTP）全程 MITM 代理 :8788 留痕+CA 验证
  • planner.go 实读：killWork/steerWork 引擎回调（运行中意图可杀/可中途改向）· transcript 原始会话持久化 · compaction 上下文窗口

发现 4 · 三大自主性机制（核心创新Ⅲ）

过程级信息交换 / 共享 todolist / 人在环路三面

  • 机制1 黑板：worker 每步 activity 落过程库；战友 search_all_worker_traces(q) 检索命中步骤→get_worker_trace 取完整过程——fact 还没写进图，观察已经被复用
  • 机制2 攻击链稳定器：planner 共享 todolist 按任务保留跨唤醒常驻，把串行利用链「记录一次、分轮派发」——事件驱动下多步链不乱序不重复
  • 机制3 人在环路三面：mainagent 对话+审批卡（AegisHook 可展开详情）/ retester 复测三态（仍可复现/已修复/无法确认，已修复自动同步）/ sidequestion 侧问（CONTEXT_BUDGET 预算管理）
  • 对照：todolist≈探隐引擎总线正缺的稳定器（已排 W5 常驻规划者）· 过程交换≈trace-search 借脑项 · retester≈P4 重放的时间维延伸

发现 5 · 12 维能力矩阵判词

ARTEX 优 4 维 · 探隐代差 3 维 · 其余各有胜负

  • ARTEX 优：多 agent 并发（planner+worker×N 可 kill/steer）/资产建模（双图+锚点+ScopeSentry 同步）/UI 可视化（全套 vs CLI+TSV）/工程成熟度（自更新回滚/LLM 池/通知）
  • 探隐代差：证据纪律（E-index 可重放卡+三态+精度门 vs 流量 MITM 被动录）/防篡改审计（timeline 哈希链 vs Postgres 可改）/效果测量（×12 战+McNemar+Levene vs 无召回/GT/统计）
  • 探隐另优：幻觉防御（无 VERIFIED 不计分）/预算纪律（budget 执法+gate-fail）/移植性（python3 零依赖跨 5 宿主 vs 需 Postgres）/授权适配（授权链内建 vs AGPL 不限使用改码分发须开源）

发现 6+7 · 战力直观对比 与 终局合体方案

双方从未同台测量（定性评估）——靶场对标实验（56-GT·n=3·同 scorer）就是要补的数据空白

  • 合体架构三层：ARTEX 引擎层（广度：planner+worker×N 并发/双图/覆盖图/过程交换/llmpool failover，产假设不产发现）→ 探隐 intents 层（裁判：意图池统一排序，置信度×矩阵新颖度，engine-hyp 配额≤40% 保自主广度）→ 探隐实证+账本层（签名：重放三态+精度门+timeline 哈希链+CVSS+McNemar 实验面）
  • 前置关卡（预登记）：同 56-GT 靶场·各 n=3·同 scorer（keying v8）·测召回+精度（幻觉率）+耗时 → 数据定「用它的引擎层」还是「只借机制」
  • 最终判断（原文）：不是「用别人工具 vs 自建」，而是「广度引擎 vs 签名能力」——探隐缺 ARTEX 的编排成熟度（能借，免疫 AGPL 只借思想）；ARTEX 缺探隐的证据灵魂（借不走）
