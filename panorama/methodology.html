一、交战生命周期：从授权到报告的八步

一人红队的项目骨架沿 PTES 全流程展开：授权定边界，侦察与攻击面分析定入口，打点拿立足，提权与横向扩大影响，收尾守合规，报告是唯一交付物。每一步先问「这一步的事实够不够支撑下一步」。

① 授权与范围依据合同/授权书确认资产清单、测试时间窗与排除项（DoS、社会工程学、物理），没写进范围的等于没测决策：IPS 告警阈值与静默要求写进 RoE
② 侦察子域收集、端口与服务扫描、Web 指纹、目录爆破与 JS 提取，被动信息源先行决策：小步快跑，不上来全端口轰炸——慢、吵、触发防护
③ 攻击面分析建入口点清单、参数枚举、指纹→CVE 比对，按信任边界给资产分组决策：先回答「哪些入口没被中间件挡住」，鉴权缺失面优先
④ 打点用注入、越权、未授权访问、反序列化、文件上传等拿 webshell 或低权限 shell决策：凭据是事实不是终点——先枚举它能碰的资产
⑤ 提权本机收集四问（我是谁/在哪/周围有谁/谁管我），Windows 四条主干与 Linux SUID/sudo 判断流程决策：先摸清杀软/EDR 清单再选提权路径
⑥ 横向隧道与代理链、凭据获取（SAM/LSASS/DPAPI），非域与域环境 Kerberos 横向，指向域控决策：域判断先于一切——机器账户/DNS/时间同步三特征确认是否域内
⑦ 收尾痕迹处理与合规收尾：清环境、清残留数据，全程不出授权范围决策：清理动作同样受 RoE 约束，证据先按 VULN-xxx 目录归档
⑧ 报告六节结构组装 + POC 卡片 + CVSS 3.1 评级 + 证据脱敏，附复测四态口径决策：结论先行；交叉三查——概述数字＝矩阵合计＝明细条数

二、四大方法论框架对照

四个框架各管一段：流程、覆盖度、行为对照、叙事。选型口诀——项目管流程用 PTES，Web 覆盖度用 WSTG，内网阶段用 ATT&CK 自查，报告叙事用 Kill Chain。四者不互斥，完整交付里都会出现。

框架是什么何时用局限（分工之外）
Kill Chain网络杀链（Lockheed Martin 七阶段：侦察→武器化→交付→利用→安装→命令与控制 C2→目标行动），攻击者视角的攻击链叙事模型报告「攻击路径」章节：把打点→立足→横移→落地写成故事线只回答「路径怎么讲」，不提供测试用例与覆盖度兜底
PTES渗透测试执行标准，七阶段：前期交互→情报收集→威胁建模→漏洞分析→渗透利用→后渗透→报告，管项目全流程的方法论立项与范围（Scope）谈判、交付物定义；一人红队的项目骨架管流程骨架，不含 Web 用例与内网 TTP 对照（用例看 WSTG，内网看 ATT&CK）
OWASP WSTGWeb 安全测试指南（稳定版 v4.2），按信息收集、配置与部署管理、身份认证、授权、会话管理、输入校验、错误处理、加密、业务逻辑、客户端等大类组织数十个用例Web 系统性覆盖度兜底「该测的都测了」；也是报告「测试方法」章节的引用来源只覆盖 Web 系统性测试，项目流程与内网行为不在其分工内
MITRE ATT&CK对抗战术/技术/常识知识库：真实攻击组织 TTP（战术/技术/过程），企业版矩阵按战术列技术内网行为对照：把内网每个动作映射到技术编号，度量红队覆盖面与蓝队检测盲区是行为知识库不是执行标准，不提供立项流程与 Web 用例级指导

三、黑盒信息渐进决策模型：缺口→下一动作

黑盒卡住的实质是事实缺口：不知道某类信息，所以不知道下一步做什么。人工版照抄 MITRE Caldera 的 facts 机制：维护 facts 表（列：事实 / 值 / 来源 / 时间），每个缺口对应一类收集动作，动作产出新事实，直到事实组合满足某条利用路径的前置条件。

信息缺口下一动作（示例可直接复制）要点
不知道资产面（子域）subfinder -d example.com被动源互不相同，多工具结果合并去重；参数以官方文档为准
不知道端口与服务nmap -sV -sC -p- <目标IP> -oA evidence/nmap_full-sV 服务版本、-sC 默认脚本、-p- 全端口、-oA 三格式输出存证
不知道 Web 指纹whatweb http://<目标>指纹是「指纹→版本→已知 CVE 比对」快通道的输入
不知道目录结构ffuf -w /opt/SecLists/Discovery/Web-Content/common.txt -u http://<目标>/FUZZ -mc 200,301,302,403字典决定上限；先小字典，再递归+扩展名
拿到一个有效凭据先枚举它能碰的资产，再评估提权凭据是事实，不是终点
  • 落表：每完成一步立即把结论写入 facts 表——写结论，不贴原始输出。
  • 验证：任一时刻你说得清「下一步动作由表中哪条缺口驱动」，说不清的动作不做；当某条利用路径的前置条件（如可达端口＋存在组件＋可用凭据）全部闭合时，能明确写出「已满足」。
陷阱：①上来全端口轰炸——慢、吵、触发防护，应小步快跑；②收集不落表，碰到同目标全部重来；③把「扫完了」当「收集完了」——原始输出不是事实，提炼出的结论才是。

四、审计员 → 渗透者：思维转换表

5 年源码审计的直觉不能直接搬进黑盒战场：真相来源、完备性标准、边界单位、验证方式、影响评估、时间模型全部要换轨。核心转换——代码即真相 → 响应即真相 + 证据链。

维度源码审计（旧我）渗透测试（新我）
真相来源代码即真相响应即真相 ＋ 证据链
完备性覆盖所有调用点与污点汇聚点（sink）覆盖率让位于「路径打通」：打通一条链比列十条可疑更有价值
边界单位函数 / 模块 / 数据流资产 / 信任边界 / 网络分区
验证方式写 PoC 代码、读单测可复现 POC 卡片 ＋ 成对请求响应留档
影响评估漏洞原理层面打通后的影响放大：提权、横向移动、核心数据
时间模型基本不受限授权窗口（测试时间窗）硬约束，动作要排优先级
🔗

「响应即真相」工作流

黑盒下唯一可信的输入是服务端返回：状态码、响应头/体、时序、带外（Out-of-Band）回连。①全流量过代理：浏览器挂 Burp Suite Proxy，测试期间禁止直连；②每个测试点先发一次基线（Baseline）请求再发 payload，两条都留档；③判定信号写进用例：回显差异（响应体/长度变化）、时延差异（与基线对比）、带外信号（DNSLog/自建监听）；④结论一律引用 Burp History 条目号或导出文件名——任何结论可被第三人回放。

证据链＝请求响应成对留存＋时间戳＋判定标准
⚖️

验证口径与降级规则

任取一条结论，在 Burp Repeater 重放所引请求，应得到与记录一致的响应；做不到的降级为「疑似」，不得写入报告。三个断链陷阱：只看页面渲染不看原始响应，漏掉注释、隐藏字段、状态码差异；在浏览器 DevTools 里改参数导致代理没记录；截图只截「结果」不截「请求」。审计优势仍可迁移：白盒技能折算成黑盒打法——先构造假设再验证，知道「这个洞对应的那个请求长什么样」。

Repeater 重放一致 → 写报告；不一致 → 降级「疑似」
