探隐 TanYin —— 让 AI 自动做渗透测试、但每一步都被系统管住的工程平台。
每一步留痕AI 的每个动作、看到的每个结果，都当场写进 13 本电子台账；记录之间用密码学哈希串成链，事后改一个字都会暴露。
越界拦得住测试范围本身也是数据。任何指向授权范围外的目标，会在账本、执行通道、宿主环境、网络出口四道关卡被依次拦截——拦截这个动作本身也留痕。
结果可复核『测完了』不是 AI 说了算：覆盖矩阵每格有状态、每个发现必须挂证据、报告出口有零泄漏终检——任何人都能用命令重放验证。
把安全测试从『老师傅手艺』变成可审计、可交接、可复算的工程流程——AI 出效率，系统守底线。
165 项自动化测试全绿 41 条账本命令黄金回归锁定 界外诱饵四层全拦 5/5 注入样本拦截率 100%·零误报

全景图：八个环节怎么接起来

纵向即真实时序：从接活到交付；每个环节顶部彩色条是内部运转机制（机制微图）；下方卡片=该环节的关键角色（绿=台账：系统的记事本）。

授权与立项 把接活儿变成受控的数据——先有边界，再开工

授权书存证 → add-goal 立项落账 → scope 白名单 → 矩阵钉列+冻结

授权书+指纹

这是啥本次测试的合同/授权扫描件，附内容指纹

为啥存在授权是法律边界，开工前先存证防抵赖

怎么运转双哈希入证据库，事后任何篡改可验出

goals.tsv 项目档案

这是啥本次测试的一页档案袋：目标、时间窗、预算、紧急联系人

为啥存在无档案不开工——先有约束再干活

怎么运转一条命令写入，字段缺一直接拒收，没有先记上再补

scope.tsv 授权白名单

这是啥允许打哪些域名/网段、明确排除哪些

为啥存在越界必须有机器可判的定义

怎么运转只加行不删行；改范围必须留审批链，历史可追

matrix 覆盖矩阵

这是啥覆盖率总表：资产乘以漏洞类型，每格为未测/已证实/不适用

为啥存在测全了没有要可度量，先定义分母

怎么运转列由行业词表 WSTG v4.2 钉死，开工即冻结，收敛判定有基准

▼ 立项完成、矩阵分母冻结 → 发动机启动 ▼

P3 演进循环（发动机） 每轮固定节奏，转到收敛或预算尽为止

⓪预算/断点检查 → ①扫台账找信号 → ②假设风暴(五路) → ③并行派发 → ④验证落账 → ⑤攻击链推理 → ⑥收敛判定→回⓪

intents.tsv 攻击意图台账

这是啥每个『我打算测什么』一行，带状态与去向

为啥存在AI 的计划本身要可审计、可复查

怎么运转派发前查预算余量，超支直接拒立项

findings.tsv 发现台账

这是啥疑似漏洞清单：在哪个资产、什么等级、挂哪些证据

为啥存在结论必须挂证据，不允许『我觉得』

怎么运转不带证据编号的发现直接拒收（铁律）

E-index.tsv 证据索引

这是啥每条原始证据（报文/截图）一行索引+双哈希

为啥存在证据防篡改、报告引用可回溯到原件

怎么运转工件先算哈希再登记，复核时可重算比对

▼ 循环产生的记录连成图谱 → 出口统一验证 ▼

十种边（台账连成推理图谱） 单表是清单，连起来才有推理：攻击链、归因、知识召回

意图 spawns 派生 → 技法 yields 产出 → 证据 proves 证实 → 发现 supersedes 合并 → 先例 derived_from 引用

边=台账间的引用关系

这是啥台账 A 的某行指向台账 B 的某行，共 10 种有方向的边

为啥存在连点成网后才能问：这条发现被什么证据撑着、这招上次在哪用过

怎么运转加边也是一条命令，方向错了拒收，图谱永不乱指

攻击链样例

这是啥意图→技法→证据→发现→影响，五连成链

为啥存在领导要的『这个漏洞怎么打出来的』一句话可答

怎么运转链由账本数据即时重建，不是事后手写的故事

▼ 图谱通过四道终检 → 才允许出报告 ▼

验证与交付（脏账不出报告） P3 转了几十轮几百行账——出口前全部重新验一遍

validate 全表校验 → hash-recheck 证据重算 → converge-check 收敛判定 → redact-scan 密钥终检 → 人签发

timeline.tsv 时间线+哈希链

这是啥所有写操作的事件流，每条含前一条的指纹

为啥存在追加式历史：事后篡改或删记录必然断链

怎么运转每条写命令自动记事件；验链命令随时全量复验

报告门

这是啥导出前的四道终检+人工签发

为啥存在正式渗透报告是法律文书，出口必须守门

怎么运转任一检失败=阻断导出；签发动作本身落账留痕

▼ 交付后经验入库 → 反哺下一轮循环 ▼

知识飞轮（打一仗强一次） 经验在人脑里会流失，在库里会复利

本次发现 → staging 暂存 → 四门槛评审 → 技法/先例知识库 → 下次风暴召回

知识沉淀管线

这是啥每场测试的打法、先例结构化入库

为啥存在第二次遇到同类系统直接召回打法，不从零开始

怎么运转入库有门槛：可复现、非重复、有证据、已脱敏——垃圾进不来

▼ 知识就位，进入日常运转层 ▼

运行时（执行通道） 账本上拒绝不等于技术上拦住——执行层要真拦

危险命令黑名单 → 界外目标拒执行 → 取执行票(留痕) → 参数化执行 → 输出自动抹密钥

guard 包装器

这是啥所有对外命令的必经之门（五段流水）

为啥存在AI 生成命令不可直接上系统，必须过闸

怎么运转黑名单→范围校验→留票→无 shell 拼接执行→输出兜底脱敏

vault 凭据保险柜

这是啥客户账号密码加密存放，AI 全程只见代号

为啥存在密钥永不进对话、永不进报告

怎么运转执行瞬间才解密注入；输出里出现真值立即还原成代号

▼ 执行与知识都在四层执法之下 ▼

恒在执法（四层关卡） 同一条授权边界，四道独立的闸纵深叠防

界外请求 → Tier0 账本拒收 → Tier1 guard 拒执行 → Tier2 宿主拦截 → Tier3 网络出口白名单

四层纵深

这是啥账本→执行→宿主→网络，层层独立设卡

为啥存在任何单层都可能被绕过，纵深保证漏一层还有下一层

怎么运转定期放界外诱饵演习：任何一层放行=事故级失败

canary 界外诱饵

这是啥系统自己生成一批假目标当靶子去打

为啥存在拦不拦得住要实证，不能靠声明

怎么运转四档位分别探测，结果写进报告守门声明

▼ 执法之下仍能断点续跑——长战役打不死 ▼

断点续传（打不死的战役） 上下文会满、会话会断、机器会掉电——战役不丢、接着干

上下文将满/会话中断→state.md 快照存档→开新会话→resume-kit 白名单注入→幂等续跑（不重做已完成）

state.md 断点快照

这是啥整场战役的一页进度存档：进行到哪步、下一步干嘛、关键结论在哪

为啥存在AI 会话有寿命（上下文窗口会满），活不能跟着会话一起死

怎么运转每轮循环结束落一版快照（不超过 200 行），重启后第一件事就是读它

resume-kit 恢复注入

这是啥新会话开机时的装机清单，只注入白名单内的关键状态

为啥存在全量历史既塞不进新会话，也会把旧噪音带进来污染判断

怎么运转快照+台账要点按白名单注入，其余一概不带——新会话干净上岗

工件即缓存（幂等续跑）

这是啥已完成的意图和证据全在台账里，重启后直接跳过不重做

为啥存在断点续传不是从头再来，得能接着上次的进度

怎么运转重放=重读不重算；已完成的意图不再派发，账本本身就是缓存

逐步推演：每一步谁在动、命令是什么、账本多了哪一行

十个关键步骤贯穿 P0 授权 → P6 沉淀；绿条=账本真实新增的行；红字=不过不放行的门禁。

S1立项落账

谁+输入：总控 + 用户问卷答案（目标/时间窗/预算/紧急联系人）
动作：
add-goal --target https://shop.example --budget 2000000;50000;40 ...
账本新增：
goals.tsv 新增：G-g1 | https://shop.example | 全量Web+白盒 | 时间窗 09-18~09-25 | 预算 2M;50000;40
⛔ 门禁：授权字段不全（无合同指纹/无签署人）直接拒收
→ 下一步：范围白名单落账（S2）

S2范围白名单

谁+输入：总控 + 问卷中的范围/排除项
动作：
add-scope --kind=include --matcher=*.shop.example；--kind=exclude --matcher=10.10.2.0/24
账本新增：
scope.tsv 新增：S-g1-001 include *.shop.example；S-g1-002 exclude 10.10.2.0/24（生产库网段）
⛔ 门禁：格式非法拒收；此后改范围必须走审批链命令
→ 下一步：覆盖矩阵初始化（S3）

S3矩阵钉列冻结

谁+输入：总控 + 行业词表 WSTG v4.2
动作：
matrix-init --vocab shared/VOCAB.md
账本新增：
matrix.tsv 生成：web.api x wstg-authn = 未测 …… 共 24 格（资产类 x 漏洞类）
⛔ 门禁：词表版本钉死；分母冻结后『测全了』才有基准
→ 下一步：开工侦察（S4）

S4侦察发现资产

谁+输入：测绘引擎 + 域名/端口扫描结果
动作：
add-asset --name=api.shop.example --type=webapi
账本新增：
assets.tsv 新增：AST-g1-0002 | api.shop.example | webapi | 互联网可达
⛔ 门禁：界外资产会被 scope-check 标记，不进矩阵分母
→ 下一步：生成攻击意图（S5）

S5生成攻击意图

谁+输入：总控 + 知识库召回的打法
动作：
add-intent --title=验证登录绕过 --kind=authn-bypass --budget-share=100;10;1
账本新增：
intents.tsv 新增：INT-g1-0002 | 验证登录绕过 | pending | 预算份额 100;10;1
⛔ 门禁：预算余量不足直接拒立项（budget-exhausted）
→ 下一步：派发执行（S6）

S6派发执行（经 guard）

谁+输入：子代理引擎 + 具体测试命令
动作：
tanyin-guard exec -- curl -s https://api.shop.example/login
账本新增：
timeline 新增：request-ticket cmd=curl（执行票：谁在何时跑了什么）
⛔ 门禁：危险命令黑名单命中/界外目标 → 拒执行且留痕
→ 下一步：取证落账（S7）

S7取证落账

谁+输入：引擎 + 原始报文/截图工件
动作：
add-evidence --title=登录绕过报文 --artifact=evidence/ev1.raw ...
账本新增：
E-index.tsv 新增：EV-g1-0001 | sha256 双哈希 | 工件路径（原件不进数据库，进哈希）
⛔ 门禁：证据内容含密钥形态（cookie/token）→ 拒落盘，先脱敏
→ 下一步：发现入账（S8）

S8发现入账

谁+输入：总控 + 证据编号
动作：
add-finding --title=管理接口匿名可读 --evidence-ids=EV-g1-0001 --confidence=0.9
账本新增：
findings.tsv 新增：FD-g1-0001 | 疑似 | 高影响 | 证据=EV-g1-0001 | 状态=active
⛔ 门禁：不带证据编号的发现直接拒收（铁律：无证据不立发现）
→ 下一步：收敛判定（S9）

S9收敛判定

谁+输入：总控
动作：
converge-check
账本新增：
输出：矩阵还有 3 格未测 / 2 个意图 pending → 继续循环；全绿 → 进交付
⛔ 门禁：有未测格、悬空引用 → 不放行出报告
→ 下一步：交付终检（S10）

S10交付终检+签发

谁+输入：总控 + 报告 + 人
动作：
redact-scan（全文密钥扫描）→ approve --verify-signoff
账本新增：
timeline 新增：redact-scan leaks=0 → signoff 事件（谁在何时批准交付）
⛔ 门禁：任何密钥残留=阻断导出；未签发=阻断导出
→ 下一步：归档+知识飞轮入库

术语小字典

页面和命令里出现的词，这里一句人话讲清——分享时不用再口述补课。

术语人话
台账/账本（ledger）TSV 表格文件，追加式记录一类事实（项目、范围、意图、发现、证据等共 13 本），是系统的唯一事实来源
追加写只许新增行、不许改旧行——历史不可篡改，错了也是追加一行更正
哈希链每条记录内含前一条的指纹，环环相扣——改任何一条，后面全部断链暴露
门禁/关卡（gate）流程里的强制检查点，不过不放行，拒绝动作本身留痕
收敛（converge）该测的都测完了的机器判定：覆盖矩阵无未测格、无悬而未决的意图
覆盖矩阵（matrix）资产 x 漏洞类型的总表，每格一个状态——回答测全了没有
边（edge）台账行与行之间有方向的引用关系（共 10 种），连成图谱后可推理可召回
证据双哈希证据原件算两种指纹登记——复核时重算比对，防调包
预算三元组token 数;请求数;工时 三种资源上限，花超了系统自动停，防跑飞
占位符 {{vault:cred-N}}凭据的代号写法——AI 和报告里永远只见代号，真值锁在保险柜
Tier 0-3（四层关卡）同一条授权边界的四道独立拦截层：账本→执行通道→宿主环境→网络出口
黑盒/白盒黑盒=不给源码从外测；白盒=给源码从里读——探隐两种都支持
Nday已公开但目标可能没修的老漏洞——用公开情报先验再实测验证
知识飞轮每场测试的打法沉淀入库、下次召回复用——经验复利机制
单写者同一时间只允许一个组件写账本（命令箱），从机制上消灭并发写坏
红队（red team）攻方视角的安全测试：在授权范围内模拟真实攻击者找漏洞
断点续传/受管重启AI 会话断了或上下文满了，系统自动存档、换新会话接着干——战役进度不丢
state.md断点快照：一页纸写清战役进行到哪、下一步是什么——重启后的第一读物
幂等续跑已完成的工作在台账里直接复用，重放只重读不重算——不从零再来
