交战思维 · 方法论原典 × 系统执法

本页两层：上半=交战思维原典（methodology.html，2026-09-21 定稿，面向人手的渗透方法论——方法论源头，全部精华逐条吸收，一字不丢）；下半=同一套思想的系统执法版（从授权到报告的六步，每步标注「执法件」=不用人盯、违规自动拒的关卡）。原典教人怎么想，执法版把想法焊进机器——两层的对应关系贯穿全页。

原典 · 一、交战生命周期：从授权到报告的八步

一人红队的项目骨架沿 PTES 全流程展开——每一步先问「这一步的事实够不够支撑下一步」

步骤做什么决策点（原典原文）
① 授权与范围依据合同/授权书确认资产清单、测试时间窗与排除项（DoS、社会工程学、物理）没写进范围的等于没测；IPS 告警阈值与静默要求写进 RoE
② 侦察子域收集、端口与服务扫描、Web 指纹、目录爆破与 JS 提取，被动信息源先行小步快跑，不上来全端口轰炸——慢、吵、触发防护
③ 攻击面分析建入口点清单、参数枚举、指纹→CVE 比对，按信任边界给资产分组先回答「哪些入口没被中间件挡住」，鉴权缺失面优先
④ 打点用注入、越权、未授权访问、反序列化、文件上传等拿 webshell 或低权限 shell凭据是事实不是终点——先枚举它能碰的资产
⑤ 提权本机收集四问（我是谁/在哪/周围有谁/谁管我），Windows 四条主干与 Linux SUID/sudo 判断流程先摸清杀软/EDR 清单再选提权路径
⑥ 横向隧道与代理链、凭据获取（SAM/LSASS/DPAPI），非域与域环境 Kerberos 横向，指向域控域判断先于一切——机器账户/DNS/时间同步三特征确认是否域内
⑦ 收尾痕迹处理与合规收尾：清环境、清残留数据，全程不出授权范围清理动作同样受 RoE 约束，证据先按 VULN-xxx 目录归档
⑧ 报告六节结构组装 + POC 卡片 + CVSS 3.1 评级 + 证据脱敏，附复测四态口径结论先行；交叉三查——概述数字＝矩阵合计＝明细条数

深读指引（原典）：VOL-07-08 方法论·报告交付（PTES 流程与 PART B 六件交付物）· VOL-01 Web 渗透·上（侦察与攻击面）· VOL-03 内网渗透（提权/横向/收尾）· VOL-06 工具链（工具输出怎么读、RoE）。

系统执法版对应：八步的骨架就是九道门（P0 授权→P1 范围→P2-P3 执行→P4 验证→P5 报告→P5.5 签发→P6 清理→P6.0 沉淀）——原典的「每一步先问事实够不够」，机器版=intents 不蒸发律+发现必附证据边。

原典 · 二、四大方法论框架对照

四个框架各管一段：流程、覆盖度、行为对照、叙事——四者不互斥，完整交付里都会出现

选型口诀（原典原文）：项目管流程用 PTES，Web 覆盖度用 WSTG，内网阶段用 ATT&CK 自查，报告叙事用 Kill Chain。
框架是什么何时用局限（分工之外）
Kill Chain网络杀链（Lockheed Martin 七阶段：侦察→武器化→交付→利用→安装→命令与控制 C2→目标行动），攻击者视角的攻击链叙事模型报告「攻击路径」章节：把打点→立足→横移→落地写成故事线只回答「路径怎么讲」，不提供测试用例与覆盖度兜底
PTES渗透测试执行标准，七阶段：前期交互→情报收集→威胁建模→漏洞分析→渗透利用→后渗透→报告立项与范围（Scope）谈判、交付物定义；一人红队的项目骨架管流程骨架，不含 Web 用例与内网 TTP 对照
OWASP WSTGWeb 安全测试指南（稳定版 v4.2），按信息收集/配置部署/身份认证/授权/会话管理/输入校验/错误处理/加密/业务逻辑/客户端等大类组织数十个用例Web 系统性覆盖度兜底「该测的都测了」；报告「测试方法」章节的引用来源只覆盖 Web 系统性测试，项目流程与内网行为不在分工内
MITRE ATT&CK对抗战术/技术/常识知识库：真实攻击组织 TTP，企业版矩阵按战术列技术内网行为对照：把内网每个动作映射到技术编号，度量红队覆盖面与蓝队检测盲区是行为知识库不是执行标准，不提供立项流程与 Web 用例级指导

系统执法版对应：WSTG v4.2 是 matrix.tsv 攻击面×漏洞类矩阵的列词表（P1 出口断言列从词表钉死、全覆盖才放行）；ATT&CK 映射=L3 自测项「能用编号映射自己用到的技术」。

原典 · 三、黑盒信息渐进决策模型：缺口→下一动作

黑盒卡住的实质是事实缺口——不知道某类信息，所以不知道下一步做什么（人工版照抄 MITRE Caldera 的 facts 机制）

维护 facts 表（列：事实/值/来源/时间），每个缺口对应一类收集动作，动作产出新事实，直到事实组合满足某条利用路径的前置条件。

信息缺口下一动作（示例可直接复制）要点
不知道资产面（子域）subfinder -d example.com被动源互不相同，多工具结果合并去重；参数以官方文档为准
不知道端口与服务nmap -sV -sC -p- <目标IP> -oA evidence/nmap_full-sV 服务版本、-sC 默认脚本、-p- 全端口、-oA 三格式输出存证
不知道 Web 指纹whatweb http://<目标>指纹是「指纹→版本→已知 CVE 比对」快通道的输入
不知道目录结构ffuf -w /opt/SecLists/Discovery/Web-Content/common.txt -u http://<目标>/FUZZ -mc 200,301,302,403字典决定上限；先小字典，再递归+扩展名
拿到一个有效凭据先枚举它能碰的资产，再评估提权凭据是事实，不是终点
落表：每完成一步立即把「结论」写入 facts 表——写结论，不贴原始输出。
验证：任一时刻你说得清「下一步动作由表中哪条缺口驱动」，说不清的动作不做；当某条利用路径的前置条件（如可达端口＋存在组件＋可用凭据）全部闭合时，能明确写出「已满足」。
陷阱三则（原典原文）：①上来全端口轰炸——慢、吵、触发防护，应小步快跑；②收集不落表，碰到同目标全部重来；③把「扫完了」当「收集完了」——原始输出不是事实，提炼出的结论才是。

系统执法版对应：facts.tsv=「一行一事实碎片，只记观察到的不记结论」；未消费 fact=下一个假设的燃料（derived_from 反哺新意图——探索循环的引擎）；authz-diff 前置硬门=引用 CRED 必须 active。

原典 · 四、审计员 → 渗透者：思维转换表

5 年源码审计的直觉不能直接搬进黑盒战场——真相来源、完备性标准、边界单位、验证方式、影响评估、时间模型全部要换轨

维度源码审计（旧我）渗透测试（新我）
真相来源代码即真相响应即真相 ＋ 证据链
完备性覆盖所有调用点与污点汇聚点（sink）覆盖率让位于「路径打通」：打通一条链比列十条可疑更有价值
边界单位函数 / 模块 / 数据流资产 / 信任边界 / 网络分区
验证方式写 PoC 代码、读单测可复现 POC 卡片 ＋ 成对请求响应留档
影响评估漏洞原理层面打通后的影响放大：提权、横向移动、核心数据
时间模型基本不受限授权窗口（测试时间窗）硬约束，动作要排优先级

审计优势仍可迁移：白盒技能折算成黑盒打法——先构造假设再验证，知道「这个洞对应的那个请求长什么样」（VOL-04 源码审计→黑盒联动：审计员优势的降维打法）。

系统执法版对应：W4 白盒双车道=「代码发现→渗透意图 / 黑盒异常→代码复核」双向派生（deepex 型）——这张转换表是白盒车道的产品化。

原典 · 五、「响应即真相」工作流 与 验证口径

黑盒下唯一可信的输入是服务端返回：状态码、响应头/体、时序、带外（OOB）回连

🔗「响应即真相」工作流（四步）

①全流量过代理：浏览器挂 Burp Suite Proxy，测试期间禁止直连；②每个测试点先发一次基线（Baseline）请求再发 payload，两条都留档；③判定信号写进用例：回显差异（响应体/长度变化）、时延差异（与基线对比）、带外信号（DNSLog/自建监听）；④结论一律引用 Burp History 条目号或导出文件名——任何结论可被第三人回放。

证据链＝请求响应成对留存＋时间戳＋判定标准。

⚖️ 验证口径与降级规则

任取一条结论，在 Burp Repeater 重放所引请求，应得到与记录一致的响应；做不到的降级为「疑似」，不得写入报告。

三个断链陷阱（原典原文）：只看页面渲染不看原始响应，漏掉注释、隐藏字段、状态码差异；在浏览器 DevTools 里改参数导致代理没记录；截图只截「结果」不截「请求」。

Repeater 重放一致 → 写报告；不一致 → 降级「疑似。

系统执法版 · 六步横向流程（从授权到报告）

九道门全程护航，门序单源自代码 core.GATE_ORDER，界面词表一字不差

① 八问授权

门 P0 授权确认

建任务先答八问：授权件（原件+sha256+签署方）/窗口期/范围白名单/紧急联系人/预算/凭据来源/强度档/法律条款。

执法件：缺一=422 整单拒（server.py:316 八问校验）；授权四件落 goals.tsv；范围落 scope.tsv；凭据真值永不进账本（vault 占位符）。

➜

② 意图链

门 P1 范围检查 · P2 预算

任务拆成一条条意图（intents.tsv），战士领取打租约（时限标记），超时自动回收重授；无可用引擎=blocked 留因，不静默丢。

执法件：双抢互斥 REJECT；租约超时先落 blocked[lease-expired] 回收行再重授；预算三维（token/请求/时长[$]）触帽=优雅停+收尾令。

➜

③ 战士执行

门 P3 执行

自研 AI 大脑循环：领意图→组上下文（50 张技法卡按意图检索注入+上轮自纠信号）→选模型道→发 JSON 指令→调工具→写账。

执法件：每条工具命令过守卫门链（黑名单/范围界外/限速/审批档）；资源三帽（CPU/进程/内存）；心跳+停滞自杀重生交租约；断点续跑按 timeline 末行重建。

➜

④ 机械重放验证

门 P4（发现入卷硬门）

每个发现由独立进程原样重放（tanyin-replay，上限 3 次）；重放不过=不算漏洞。

执法件：未验证不入卷——SARIF 只收已验证（report_artifacts.py）；验证状态三态=已验证/待验证/已失效；误报防线核心=机器复算，非人肉双签（#17 修订 C 用户裁定）。

➜

⑤ 复测

门 P5 复测

对「已修复」候选自动排队复测；复测页已建成待挂载。

执法件：复测走 rerun 门（gate reset 重走门序）；账本 supersede 墓碑——翻案留全史，后代行胜。

➜

⑥ 报告签发

门 P5.5 报告→签发 · P6 清理 · P6.0 沉淀

报告中心：六节预览、渲染输入哈希钉（同输入同输出）、版本链、签发位（草稿→待签发→已签发锁定）。

执法件：渲染纯函数两跑哈希比对；pass.json 绑定逐件复检，篡改=红条不回退；战毕过清理门（P6）清痕——仓净 0 行/容器 0 残留为验收。

三条全程律（哪一步都在管）

范围·预算·留痕——原典的 RoE/时间窗/证据链三决策，机器版的形态

范围执法：四层拦截（账本/执行通道/宿主 hook/出口代理）+scope 四 kind 匹配+deny-list 黑名单单源；范围外发现走分域异步扩展审批（宪法 #45：门按域分不整体停），全停仅限法务红线（窗口到期/急停/预算硬顶）。原典对应：①授权与范围「没写进范围的等于没测」。

预算执法：token/请求/时长（美元）三维预算树；超限=BUDGET-ENFORCE 收尾令重启（HANDOFF F3）；预算触帽时间窗优雅停。原典对应：时间模型「授权窗口硬约束，动作要排优先级」。

留痕执法：每一步（含拒绝本身）写 timeline.tsv 哈希链行——任意历史时刻可回放（演变回放条：帧号=记录行号）、可第三方验真（verify-chain）。原典对应：证据链「请求响应成对留存＋时间戳＋判定标准」。

为什么这样设计（三句）

原典的「响应即真相」→系统的「机械重放」——一条思想线

  1. 误报是生死线（宪法 #43）：所以验证不是「模型说算」而是机械重放——机器复算才算数；原典同款：Repeater 重放不一致=降级「疑似」不得入卷。
  2. 授权是地基：八问缺一不开仗，凭据真值永不进账本——安全产品自己先不能成为泄露源；原典同款：没写进范围的等于没测。
  3. 越打越强要能证明：打法沉淀成 50 张技法卡按意图注入，评测棘轮管能力回归——这套循环的目标是把「经验」变成「资产」；原典同款：知识飞轮（四门槛入库，开局指纹召回）。
