ARTEX（竞赛冠军 · 广度优化）

工位做法判
规划planner 拆链 + 共享 todolist 分轮派✅ 强
执行worker×N 并发 + 真工具 + MITM 录流量✅ 强
记录2 逻辑图落 1 个可变 Postgres（给 LLM 看）⚠️ 给 LLM 看
验证无独立重放，agent 自己写发现❌ 幻觉可进图
交付UI 报告+覆盖图，无 GT 无统计❌ 无测量

它的账是给 agent 用的工作记忆：合并成图方便 LLM 读态势——竞赛里这是对的（快抢分）；风险链=发现由 agent 写图→无第二方复验→幻觉发现与真发现同形→直接进报告；改库=改历史（Postgres 单点可变，无链无门）。

图C · 三条后果链：「直接用」的机制推演（不是观点）

竞赛场景都不罚（快抢分就赢），交付场景都致命——这就是目标函数差异

① 幻觉链：

agent 写发现▼无第二方复验▼幻觉与真发现同形▼假发现进客户报告▼信誉一次性破产

探隐断点：evidences 边 + P4 机械重放 + 无 VERIFIED=0 分（烂帐连坐逼战士自纠）

② 篡改链：

单点可变 Postgres▼有库权限即可改史▼审计只能选择相信▼交付不可辩护

探隐断点：timeline 哈希链（改一行断链可检）+45 条 CLI 前置校验（嘴说无效）

③ 测量链：

从未测过召回/精度▼换工具=盲换▼无法给承诺▼出问题无法归因

探隐断点：56-GT 分母召回 ×12 战 + McNemar + 双臂——每次改动都有判决

图D · 决策树与终局合体（广度归它 · 签名归我）
