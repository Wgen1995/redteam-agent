侦察组 —— 黑盒第一步：攻击面在哪、门后是什么

工具做什么一句话原理核心命令陷阱
nmap
详解 →		 端口与服务侦察基座：目标开了什么门、门后是什么服务 默认 SYN 半开扫描只发 TCP 握手前两步，收到 SYN/ACK 即判开放并 RST 断开；-sV 发协议探针与签名库比对出版本；NSE 内嵌 Lua 虚拟机按脚本分类联动检测 sudo nmap -sS -sV -p- 192.168.10.5 -oA recon/full_tcp
UDP 补扫：sudo nmap -sU --top-ports 50		 只扫 TCP 会漏 UDP（SNMP/NTP 在那）；不加 sudo 时 -sS 静默降级为更吵的全连接；客户环境用 -T2~T3 --max-rate，-T4/-T5 留给靶场
httpx
详解 →		 给大列表（域名/IP/URL）做「谁活着、什么站、什么技术栈」的快速过滤 Go 并发发 HTTP(S) 探测（https 失败自动回退 http），按需提取状态码/标题/技术栈指纹/IP/CNAME/CDN 归属，基于 retryablehttp 做重试退避 cat subs.txt | httpx -title -tech-detect -cdn -json -o live.json
内网：-ports 80,443,8000,8080,8443 -rate-limit 50		 通配符 DNS 会把全部子域解析到同一 IP，先 -ip 聚类去重；默认只探 80/443，内网必须 -ports；大列表不配 -rate-limit 会打爆 WAF 留一堆 429 污染客户日志
ffuf
详解 →		 Web Fuzz 主力：目录/文件、参数名、参数值、虚拟主机（vhost） 把 URL 中 FUZZ 占位符替换为字典项并发请求；核心是校准（calibration）——先用随机字符串测出「软 404」基线，-ac 据此自动过滤，剩下的才可信 ffuf -w raft-medium-directories.txt -u https://target/FUZZ -ac -mc 200,301,302,403 -recursion
定制字典：cewl -d 2 -w site.dict 再与通用字典合并去重		 忘 -ac/-fs 满屏软 404 是新手第一大坑；递归是指数级流量，先 medium 后 large；WAF 目标配 -rate 50；字典工程原则：定制 > 通用
OneForAll
+ subfinder
详解 →		 子域收集，划定攻击面第一步：授权主域下有哪些子域 OneForAll 聚合多源（子域字典爆破、证书透明度日志、第三方 API、DNS 数据集）再做解析与存活校验；subfinder 走纯被动源无发包——先被动后主动，被动零告警 python3 oneforall.py --target example.com run
subfinder -d example.com -silent > subs.txt，接 httpx 存活筛选		 OneForAll 不配第三方 API key 结果明显偏少；仓库久未大更新装不上就退回 subfinder + CT 日志；爆破类收集会对权威 DNS 产生查询流量，确认授权范围覆盖 DNS

Web 代理组 —— 看包、改包、重放、批量、扫描的主战场

工具做什么一句话原理核心命令陷阱
Burp Suite
详解 →		 Web 测试工作台：看包、改包、重放、批量、扫描 本机 127.0.0.1:8080 起代理监听中转流量，HTTPS 靠 Burp 动态签发的 CA 证书做中间人（MITM）解密；所有流量进 HTTP history，任意请求可送 Repeater / Intruder / Scanner 复用 Repeater 手工重放微调（80% 时间在这）；联动 sqlmap：请求右键 Copy to file 存 req.txt → sqlmap -r req.txt --batch 系统全局代理会劫持其他工具流量（用 FoxyProxy 分模式）；不设 Target scope 就开 Scanner 会扫到第三方资源（越界+浪费）；Intruder 忘 URL 编码选项，% 破坏请求结构
mitmproxy
详解 →		 Burp 的命令行互补件：批量改包、自动校验、App/小程序抓包 同为 MITM 代理，交互模型是「插件（addon）+ 事件钩子（hook）」：Python 文件定义 request(flow)/response(flow)，每个流经过时被回调，直接改写请求/响应 mitmdump -s addon.py --listen-port 8080；手机抓包：Wi-Fi 代理指向本机，设备访问 http://mitm.it 装证书 Android 7+ 默认不信任用户证书，App 的 HTTPS 需系统级证书（root），未授权设备别碰；脚本异常会静默丢流量，前台跑盯 stderr

验证利用组 —— 把手工确认的疑点变成可复现证据

工具做什么一句话原理核心命令陷阱
sqlmap
详解 →		 SQL 注入验证与提数：指纹、提数、绕 WAF（只对授权数据） 对参数注入探测载荷，覆盖五类判定——报错型看回显、布尔盲注对比真假响应、时间盲注用延迟推断、UNION 探列数与回显位、堆叠查询；确认后按数据库方言构造提数语句 sqlmap -r req.txt --batch --level 3 --risk 2
绕 WAF/降速：--tamper=space2comment --random-agent --delay 2 --threads 1		 时间盲注大量 SLEEP 会拖垮小站连接池，生产必配 --delay 2 --threads 1 并约时间窗；--dump 仅在授权允许取数时用，合规做法是 --schema/--count 级取证；sqlmap 不是发现器，先在 Repeater 手工确认再交给它
nuclei
详解 →		 批量、可复现的已知漏洞（CVE/指纹/泄露）验证器 引擎与 YAML 模板分离：模板定义「发什么请求 + 怎么判定（matcher）+ 怎么提取（extractor）」，引擎并发渲染执行；模板即代码，可版本化、可自定义、交付时能精确复述检测逻辑 nuclei -l live.txt -severity critical,high -o recon/nuclei_high.txt
自定义模板：Burp 历史改 {{BaseURL}} 占位 + 双条件 matcher，先对靶场验证再上线		 matcher 只配 200 必误报（软 404 也 200），至少双条件；模板库滞后于新 CVE，高危新洞照官方公告思路自己写；主动/破坏类模板对生产危险，显式排除；结论措辞是「覆盖范围内未发现」而非「安全」
fscan /
vulmap
详解 →		 拿到内网立足点（或授权内网段）后的第一轮广度扫描 fscan（Go 单二进制）：ICMP 存活 → TCP 常用端口 → 服务/指纹识别 → 内置弱口令与已知漏洞 POC；vulmap（Python）面向 Web 中间件/框架（weblogic/tomcat/fastjson/shiro/spring）做漏洞比对+验证。共性：快、全、吵 ./fscan -h 192.168.10.0/24 -ao（只存活摸底）
定向：-p 22,80,443,3389 -nobr（禁爆破防账号锁定）		 弱口令爆破可能锁死域账号、触发 SIEM 应急——铁律：授权书明确允许 + 约定时间窗 + -nobr 起步 + 控制线程与网段；输出是线索清单，命中必须手工复核才进报告；在授权边界外网段跑 = 越界红线

后渗透组 —— 立足之后：利用、隧道与边界

工具做什么一句话原理核心命令陷阱
Metasploit
详解 →		 模块化利用与后渗透工具箱，内网横向的「瑞士军刀」 六类模块（auxiliary/exploit/payload/post/encoder/evasion）；每个 exploit 有前置条件（版本、路径、认证状态），不满足即失败——先侦察后利用；meterpreter 是内存驻留的多功能 shell use exploit/multi/http/tomcat_mgr_upload → show options → exploit；跳板：run post/multi/manage/autoroute + socks_proxy 再配 proxychains NAT 后拿错 LHOST（如 127.0.0.1）回连必败，用目标可达的 VPN tun0/公网 VPS；EDR 常拦 meterpreter，降级普通 shell 或先做免杀评估；不 show options 就 exploit 多半参数不全；后渗透每个动作对应授权范围，横向移动要单独确认
CobaltStrike
详解 →		 商业 C2 框架、红队协同平台——本卷只建概念与合规边界，不教操作 Team Server（监听器管理、任务分发、日志留存）+ Beacon 植入体按 sleep+jitter 周期回连（回连节奏影响被检测概率）+ Malleable C2 Profile 定制流量特征伪装成合法协议；多人共享会话视图是与单机工具的本质差别 硬前提：正版授权（Fortra 商业许可）+ 客户书面授权（RoE 列明时间窗、目标、C2 域名/IP、允许动作），缺一即违法；练手用官方培训材料或自建授权靶场，无预算用开源替代（Havoc、Sliver、MSF） 网上「破解版/汉化版」是供应链投毒重灾区，下载即失陷且使用违法（刑法 285/286 红线）；C2 基础设施未列入授权附录 = 越界；一人红队前期用不上：MSF + frp 覆盖绝大多数授权测试场景
frp
详解 →		 内网穿透隧道：把内网服务/socks 代理反向暴露到你的 VPS 反向隧道——内网侧 frpc 主动连公网 frps 建立控制连接，外部访问 frps 的 remotePort，流量经隧道转发到 frpc 侧 localPort；支持 tcp/udp/http/https 与插件扩展，socks5 插件可把失陷主机变成公网代理跳板 frpc.toml：[[proxies]] type="tcp"（内网 RDP 3389 → VPS 13389）或 socks5 插件；之后 proxychains nmap -sT -Pn 192.168.10.0/24 公网裸 frps 是扫描器重点：强 token + 非默认端口 + 面板强口令，历史版本有已知 RCE，始终用最新版；隧道用于客户环境前确认 RoE 允许「流量中转/VPS 出口」、VPS IP 列入授权附录；nmap 走 socks 只支持全连接扫描（-sT -Pn），别误判「端口全关」

辅助组 —— 编解码、胶水代码与交付的另一半

工具做什么一句话原理核心命令陷阱
CyberChef
详解 →		 编解码瑞士军刀 纯前端实现数百种运算操作（Operation），拖拽组成处理流水线（Recipe）；完全离线可用、数据不出本机——这是对在线工具的合规优势 常用：Magic（自动识别多层编码）、From Base64、URL Decode、JWT Decode；Recipe 可导出为 URL 分享复现 操作参数选错（Base64 字母表变体、字符串 vs Hex 输入）是排障第一现场；官方在线版方便但敏感数据务必用离线版
代码执行环境
详解 →		 PoC 与自动化工位：渗透一半的工作是一次性胶水代码 虚拟环境（venv）隔离依赖，脚本与命令同存入案例笔记保证可复现；PoC 模板三件套——Session 复用连接、显式关闭校验注明原因、断言产出证据 python3 -m venv ~/.venvs/redteam
jq -r '.[] | select(.status_code==200) | .url' live.json		 PoC 硬编码生产地址被他处误触发；venv 忘激活污染全局；verify=False 提交进正式工具库（应做成显式开关）
笔记与截图规范
详解 →		 交付的另一半：笔记即报告草稿 报告的证据链只能来自测试当下；每个发现（finding）一张卡，测完卡齐报告就齐——案例卡固定字段：时间/资产/工具命令/输出/截图编号/影响初判 截图规范五条：全屏含地址栏、Burp 证据请求响应成对（Raw 视图）、命令行含完整命令与关键输出、画面留系统时间、命名 YYYYMMDD_HHmm_target_caseNo_desc.png 与案例卡互引 事后补截图（时间戳对不上是硬伤）；截图泄露客户业务数据（口令打码保留证据效力，如仅露前 3 后 2 位）；工具输出无上下文（只有状态码没有 URL 等于没证据）

② 工具组合战术矩阵：场景 → 工具链 → 输出物

单工具回答「能做什么」，组合回答「什么时候用哪个」。七条链路覆盖外网测绘到证据整理的完整闭环。

外网资产测绘subfinder / OneForAll → httpx 存活指纹 → nmap -sV（真实 IP）存活资产表（url / title / 技术栈 / IP / 端口）
Web 打点ffuf 目录+参数 → Burp Repeater 手工验证 → sqlmap -r 提数finding 卡 + 请求响应证据对
已知漏洞批量验证httpx → nuclei（高危过滤）→ 命中项手工复核高危漏洞清单（附模板依据）

③ 工具选择决策要点：噪音 · 速率 · 授权边界

选工具的第一性问题不是「哪个更强」，而是「哪个在当前授权与噪音预算内最合适」——这是 VOL-06 贯穿全卷的合规主线。

🔊

噪音控制

fscan 快、全、吵：-nobr 起步、控制线程与网段——弱口令爆破可能锁死域账号、触发 SIEM 应急。nmap 诱饵 -D RND:6 只在日志层稀释，骗不过有状态防火墙；无 sudo 时 -sS 静默降级为更吵的全连接。nuclei 显式排除主动/破坏类与拒绝服务模板（-etags dos）。

侦察信息增量 > 扫描流量增量
⏱️

速率与时间窗

客户环境 nmap 用 -T2~T3 + --max-rate，IPS 告警阈值写进 RoE；-T4/-T5 留给靶场。httpx 大列表配 -rate-limit，否则 429 污染客户日志。sqlmap 生产必配 --delay 2 --threads 1 并约时间窗。ffuf 递归是指数级流量：先 medium 后 large、命中子目录再深挖。

慢即是稳：生产环境一切速率参数显式声明
📜

授权边界（RoE）

所有命令仅用于已签授权书范围内的目标：sqlmap 只对授权数据，--dump 以授权书为准，合规做法是 --schema/--count 级取证；横向移动要单独确认；C2 基础设施与 frp 的 VPS IP 列入授权附录；fscan 在授权边界外网段跑 = 越界红线；CobaltStrike 无正版授权 + 客户书面授权即违法（刑法 285/286 红线）。

授权范围 = 工具能碰的最大边界
🧭

什么时候用哪个

大列表先被动（subfinder）后主动（httpx/nmap）；批量变体优先 ffuf 而非 Intruder（社区版限速）；已知 CVE 批量验证用 nuclei 模板、新洞自己写模板；注入先在 Repeater 手工确认可疑点再交 sqlmap；fscan 命中只是线索，逐条回 nmap 精扫 / Burp / 手工 POC 复核后才进报告。

先手工确认，再自动化放大
一人红队心法：每条链路的最后一站永远是「证据落盘」。工具只是把发现变成可交付输出的管道——发现不了价值的不是工具差，是链路没接到交付物上。
